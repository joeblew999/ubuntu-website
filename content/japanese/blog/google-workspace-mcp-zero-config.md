AIアシスタントをGoogle Workspace全体に接続するのに、必要なコマンドがたった1つだとしたらどうでしょうか？

「これらの認証情報を設定し、これらのAPIを有効化し、これらの権限を設定してから再起動してください」ではありません。メールアドレスを入力するだけで、すべてが動作します。

それを私たちは実現しました。

## AI連携の問題点

AI連携の話は、どれも同じ疲れるパターンをたどります：

1. どこかの開発者コンソールでAPI認証情報を作成する
2. 十数個のAPIを手動で有効化する
3. OAuth同意画面を設定する
4. リダイレクトURIを設定する
5. シークレットをどこか安全な場所に保管する
6. 接続設定を構成する
7. ツールを再起動する
8. なぜ動かないのかをデバッグする
9. 手順3bを見落としていたことに気づく
10. 最初からやり直す

終わる頃には、翌月に節約できる時間よりも多くの時間をセットアップに費やしています。しかも、正しく動作しているのかどうかさえ、まだ確信が持てません。

## WellKnown + MCP：異なるアプローチ

[Model Context Protocol (MCP)]({{< relref "/platform/foundation" >}})は、AIアシスタントが外部のツールやデータにアクセスするための標準的な方法を提供します。WellKnownプロジェクトはこれをさらに推し進め、あらゆる複雑さを裏側で処理する自動セットアップを実現します。

以下がセットアップの全手順です：

```bash
task google-mcp:setup
```

これだけです。システムは次のことを行います：

1. **バージョン固定のMCPサーバーリリースをインストール**（未インストールの場合）
2. **Google OAuthクライアントをOSのキーチェーンに保存**し、平文のファイルには決して保存しません
3. ブラウザで**ガイド付き認証を開く**
4. 実際のCalendar呼び出しで**すべてが動作することを検証**

AIアシスタントの設定はプロジェクトに同梱されている（`.mcp.json`）ため、接続の設定は一切不要です。

手動でのAPI有効化は不要。JSONファイルの編集も不要。再起動を繰り返す必要もありません。

## どのAIでも。同じ連携。

MCPが独自仕様の連携と根本的に異なる点は、**どのAIでも動作する**ことです。

| AIタイプ | 例 | 同じMCP連携 |
|---------|----------|---------------------|
| **クラウドAI** | Claude, GPT-4, Gemini | ✓ |
| **ローカルAI** | Ollama, LM Studio, llama.cpp | ✓ |
| **ハイブリッド** | クラウドでの推論 + ローカルでの実行 | ✓ |
| **特化型** | 空間推論、ドメイン特化モデル | ✓ |
| **独自モデル** | カスタムモデル、ファインチューニング済みのデプロイメント | ✓ |

MCPサーバーは、どのAIが呼び出しているかを気にしません。クラウドのClaudeがカレンダーを要求する？動作します。ノートPCで動くローカルのLlama？同じ連携です。自社のデータセンターで動くプライベートモデル？セットアップはまったく同じです。

これはベンダーロックインの正反対です。Google Workspace連携を一度構築すれば、どのAIを選んでも動作します——今日も、明日も、そしてまったく新しいモデルが登場している5年後も。

**連携に手を加えることなくAIプロバイダーを切り替えられます。** さまざまなモデルを試したり、機能をアップグレードしたり、プライバシー要件に応じてクラウド処理とローカル処理を行き来したりしても、MCPレイヤーは変わりません。

### 特化型AI：空間推論

私たちの[空間プラットフォーム]({{< relref "/platform/spatial" >}})には、汎用クラウドモデルにはない機能を備えたローカルAIが含まれています：

- **空間推論** - 3Dの位置関係、幾何学的制約、組立手順の理解
- **センサー統合** - IoTデバイス、カメラ、産業機器からのリアルタイムデータの処理
- **ドメイン知識** - CADフォーマット、製造公差、建設仕様

この特化型ローカルAIがMCP経由でGoogle Workspaceに接続すると、強力な組み合わせが生まれます：

> 「Driveからセンサーデータを取得し、熱パターンを分析して、運用チーム宛てのメンテナンス警告の下書きを作成して」

> 「CADアセンブリからプレゼンテーションを作成し、検査スプレッドシートに基づいて公差を超えている部品に注釈を付けて」

ClaudeやGPTで動作するのと同じMCP連携が、空間認識型のローカルモデルでも動作します——ただし今度は、AIがテキストだけでなく形状を理解します。

### 得られるもの

接続すると、AIアシスタントは以下にネイティブにアクセスできます：

| サービス | 機能 |

すべて自然な会話で操作できます：

## マルチアカウント対応

ビジネスにとって興味深いのはここからです：**複数のGoogleアカウントを接続できます**。

個人のGmail。仕事用のGoogle Workspace。クライアントのアカウント。それぞれが個別に認証され、それぞれが適切なコンテキストでAIアシスタントからアクセスできます。

```
task google-mcp:auth
# Authenticate first account

task google-mcp:auth
# Authenticate second account
# The system tracks both
```

これで、AIアシスタントはアカウントをまたいで操作できるようになります：

> 「来週の火曜日に、仕事用カレンダーと個人用カレンダーで予定が重なっていないか確認して」

> 「そのクライアントのメールを仕事用アカウントに転送して」

> 「個人用とビジネス用の両方のDriveから最近のファイルを一覧表示して」

## パブリッシングとの連携

これは[WellKnownのシングルソース・パブリッシング]({{< relref "/blog/one-source-every-screen" >}})と直接統合されます。コンテンツパイプラインに、Google Workspaceがファーストクラスの出力先として加わります：

**Markdownソース → WellKnown変換 → Googleドキュメント**

Markdownで書き、適切な書式を保ったままDocsに公開。コピー＆ペーストは不要。手動での再フォーマットも不要。Webサイトを生成するのと同じソースで、Google Driveにもコンテンツを配置できます。

**スプレッドシートのデータ → パブリッシングパイプライン**

Sheetsのデータをコンテンツに直接取り込みます。製品カタログ、価格表、チーム名簿——常に最新で、常に同期されています。

**Calendar → 自動スケジューリング**

将来の日付に予約されたブログ記事から、カレンダーの予定やリマインダー、さらには関係者へのメールの下書きまで自動的に作成できます。

## 依存ではなく、自己主権

一般的なクラウド連携との決定的な違いは、**認証情報とデータがあなたのマシン上に留まる**ことです。

MCPサーバーはローカルで動作します。認証トークンはホームディレクトリに、OAuthクライアントシークレットはOSのキーチェーンに保存されます。中間のクラウドサービスがあなたのGoogleデータを見ることはありません。第三者があなたのメールやファイルにアクセスすることもありません。

Googleのサービスを使いながらも、あなた自身が管理するインフラを通じて利用します。接続を解除したくなったら、ローカルの認証情報を削除すれば完了です。ベンダーに連絡する必要も、データのエクスポートを依頼する必要もありません。

これは、[自己主権型メールインフラ]({{< relref "/blog/self-sovereign-email-ai-automation" >}})で説明した原則と一致しています：必要なサービスは使いつつ、連携レイヤーの管理権は自分で保持するということです。

## AI自動化レベルの適用

[自動化レベル]({{< relref "/blog/self-sovereign-email-ai-automation" >}})を覚えていますか？ここでもそのまま当てはまります：

**レベル1 - パターン認識**
> 「チームからの未読メールが3件あります。1件に『緊急』と書かれています。要約しましょうか？」

**レベル2 - 下書き生成**
> 「提案の締め切りに関するSarahのメールに基づいて、水曜日の納品を確認する返信の下書きを作成しました。確認しますか？」

**レベル3 - 自律的なアクション**
> 「週次レポートのスプレッドシートが更新されました。サマリーを関係者向けのドキュメントにエクスポートし、配信メールを月曜日の午前9時に予約しました。」

**レベル4 - プロアクティブ・インテリジェンス**
> 「明日クライアントとの会議がありますが、準備資料がないようです。直近の3つのメールスレッドとDrive内のプロジェクトタイムラインから作成しましょうか？」

AIが個々のサービスだけでなくGoogle Workspace全体を見渡せるようになることで、各レベルはより強力になります。

MCPサーバーは、AIアシスタントとGoogleのAPIとの間の橋渡しとして機能し、以下を処理します：

- **OAuthトークンの更新**（自動、透過的）
- **リクエストのバッチ処理**（効率的なAPI利用）
- **レスポンスの整形**（AIが扱いやすい構造化形式）
- **マルチアカウントのルーティング**（リクエストを正しいアカウントへ振り分け）

すべてローカルで動作し、すべてあなたの管理下にあります。

## はじめに

### クイックスタート（ほとんどのユーザー向け）

```bash
# From your project directory
task google-mcp:setup
```

プロンプトに従い、AIアシスタントを再起動すれば完了です。

### ステップバイステップ（細かく制御したい場合）

```bash
# 1. Install the MCP server (pinned release)
task google-mcp:install

# 2. Store your Google OAuth client in the OS keychain
task google-mcp:credentials

# 3. Authenticate with Google (opens the browser, then checks)
task google-mcp:auth

# 4. Verify everything works
task google-mcp:status
```

### 接続状況の確認

```bash
task google-mcp:accounts:list
# Shows all authenticated Google accounts

task google-mcp:status
# Full status: binary, keychain secrets, accounts, configuration
```

### アクセスの削除

```bash
task google-mcp:reset CONFIRM=y
# Removes the signed-in account tokens from this machine
# Revoke the app itself in your Google Account's third-party access settings
```

## Googleの先へ

同じパターンは他のサービスにも当てはまります。MCPがプロトコルを提供し、WellKnownが自動セットアップを提供します。現在、以下の連携を構築中です：

- **GitHub** - Issue、PR、コード検索
- **Notion** - ページ、データベース、ワークスペース
- **Slack** - チャンネル、メッセージ、スレッド
- **Linear** - Issue、プロジェクト、ロードマップ

いずれも同じ原則に従います：1つのコマンドで接続、AIによるフルアクセス、ローカルでの管理。

## 何が変わるのか

AIアシスタントがGoogle Workspaceにシームレスにアクセスできるようになると、ワークフローは根本的に変わります：

**導入前**：ツール間でコンテキストを切り替える。メールを確認する。カレンダーを開く。Driveを検索する。データをAIにコピーする。応答を得る。それを貼り付けて戻す。

**導入後**：必要なことを説明するだけ。AIがサービス間を行き来し、コンテキストを集め、アクションを実行し、結果を報告します。

ツール切り替えによる認知的負担はなくなります。インターフェースではなく、成果を軸に考えられるようになります。
