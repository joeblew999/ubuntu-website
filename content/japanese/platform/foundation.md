## 現実世界のために

インターネットは途切れます。チームは大陸をまたぎます。サーバーはあなたのものです。私たちはこの現実に合わせて構築しました。

私たちの基盤は機能の話ではありません。ソフトウェアのあるべき姿の話です。オフラインファースト。自己主権。ユニバーサルデプロイ。これらの原則は、私たちが構築するすべてのものに貫かれています。

## オフラインファーストアーキテクチャ

**インターネットなしで作業。接続時に同期。データを失うことはありません。**

実際の仕事は、WiFiが不安定な場所で行われます。建設現場、工場の現場、政府庁舎、病室、遠隔地のオフィスなどです。私たちの基盤は、接続されていることではなく、切断されていることを前提としています。

### 仕組み

| コンポーネント | 機能 |
|-----------|--------------|
| **ローカルファーストデータ** | データは遠くのサーバーではなく、まずあなたのデバイス上に存在します |
| **Automerge CRDT** | 複数人が同時に編集しても競合なくマージ |
| **バックグラウンド同期** | 接続が回復すると自動的に同期 |
| **オフラインキュー** | 操作はローカルのキューに入り、可能になった時点で実行 |

**スピナーなし。「接続が切断されました」エラーなし。ただ作業するだけ。**

## どこにでもデプロイ

**1つのコードベース。すべてのプラットフォーム。ネイティブな体験。**

同じアプリケーションがブラウザ、デスクトップ、モバイルデバイスで動作します。3つの別々の製品ではなく、どこにでもデプロイできる1つのコードベースです。

### 対応プラットフォーム

| プラットフォーム | 提供形態 |
|----------|----------|
| **Web** | あらゆるモダンブラウザ（Chrome、Firefox、Safari、Edge） |
| **デスクトップ** | Windows、macOS、Linux向けネイティブアプリ |
| **モバイル** | iOSおよびAndroid向けネイティブアプリ |

オフィスのチームはデスクトップを使い、現場作業員はタブレットを使い、顧客はスマートフォンを使います。全員が同じデータで同じシステムにアクセスします。

**一度書けば、どこにでもデプロイ。保守するコードベースは1つだけ。**

## クラウド同期オプション

**あなたのクラウド。私たちのクラウド。クラウドなし。選ぶのはあなたです。**

同期に私たちのサーバーは必要ありません。組織にとって最適なインフラに接続できます。

### デプロイモデル

| モデル | 最適な用途 |
|-------|----------|
| **Ubuntu Software Cloud** | 最速のセットアップ、運用は私たちが担当 |
| **あなたのクラウド** | AWS、Azure、GCP。あなたのインフラで私たちのソフトウェアを |
| **オンプレミス** | あなたのデータセンター、完全なコントロール |
| **ハイブリッド** | 一部のデータはクラウドに、機密データはオンプレミスに |
| **エアギャップ** | 完全に切断されたネットワーク、防衛およびセキュアな環境 |

モデル間の切り替えは？簡単です。データの保存場所によってデータ形式が変わることはありません。

**ベンダーロックインなし。クラウドへの依存を強制しません。真のデプロイの柔軟性。**

## 自己主権

**あなたのデータ。あなたのサーバー。あなたのルール。**

自己主権とは、あなたが自分のインフラをコントロールすることを意味します。「私たちの条件でホストされるあなたのデータ」ではなく、本当にあなたのものです。

### 自己主権が意味すること

- **どこでも実行** — あなたのデータセンター、あなたのクラウドアカウント、あなたのノートPC
- **コールホームなし** — 私たちのサーバーに接続しなくてもソフトウェアは動作します
- **すべてをエクスポート** — 標準フォーマット、完全なデータポータビリティ
- **使用状況の追跡なし** — あなたが私たちのソフトウェアで何をしているか、私たちには見えません
- **永久ライセンスオプション** — 私たちがいなくなっても稼働し続けられます

**これは単なるプライバシーではありません。運用上の独立性です。**

## 組み込み可能

**既存システムに統合。すべてを入れ替える必要はありません。**

組織には既存のワークフロー、データベース、IDシステムがあります。私たちの基盤はそれらを置き換えるのではなく、統合します。

### 統合パターン

| パターン | ユースケース |
|---------|----------|
| **APIファースト** | すべてにプログラムからアクセス可能 |
| **データベースコネクタ** | 既存のデータベースへの読み書き |
| **SSO統合** | 新たなログインではなく、あなたのIDプロバイダーを使用 |
| **Webhookイベント** | あなたのシステムへプッシュ通知 |
| **ホワイトラベル** | あなたのブランド、私たちのエンジン |

**システムを拡張しましょう。捨てる必要はありません。**

## Wellknown Gateway

**ビッグテックのプラットフォームに公開。関係の主導権はあなたに。**

Webのゲートウェイ（Google、Apple、YouTube）は巨大なリーチを持っています。しかし、それらに「公開する」ことは、それらに「所有される」ことを意味しません。

### 関係を逆転させる

従来のアプローチ：
```
User → YouTube (owns everything) → Your content (captive)
```

Wellknownのアプローチ：
```
User → Your Gateway → Your System (primary)
                   ↳→ YouTube (mirror for discovery)
```

**玄関口をコントロールするのはあなたです。** ビッグテックは牢獄ではなく、任意の配信チャネルになります。

### 仕組み

| 機能 | 意味 |
|------------|---------------|
| **どこでもあなたのURI** | リンクは彼らではなく、あなたのゲートウェイを指します |
| **スマートルーティング** | iOSユーザーはAppleへ、AndroidはGoogleへ、Webはあなたのプレーヤーへ |
| **ミラー公開** | YouTube、Google マップ、Apple カレンダーへコピーを自動公開 |
| **自分で所有するアナリティクス** | すべてを把握し、全員を追跡、データ共有なし |
| **出口戦略を内蔵** | リンクを壊さずに、任意のプラットフォームをルーティングから除外 |

### あらゆるものと連携

- **動画** — あなたのサーバーでホストし、リーチのためにYouTube/Twitchへミラー
- **カレンダー** — あなたのCalDAVサーバー、利便性のためにGoogle/Appleと同期
- **マップ** — あなたの地理データ、Google/Apple マップと統合
- **メール** — あなたのメールサーバー、Gmailと互換
- **ファイル** — あなたのストレージ、Drive/Dropboxへ選択的に共有

**彼らのプラットフォームに「公開」する。決して「閉じ込められない」。**

## 25年のエンタープライズ経験

**Ubuntu Softwareは1999年に創業しました。** 私たちはドットコム時代、モバイル革命、クラウドへの移行、そしてAIの台頭を通じて、エンタープライズシステムを構築してきました。

### 経験から学んだこと

- **ベンダーは消える** — 初日からデータポータビリティを考慮して構築する
- **ネットワークは落ちる** — オフラインファーストはオプションではなく、不可欠
- **要件は変わる** — オープン標準はプロプライエタリなフォーマットより長く生き残る
- **規模は予想を超える** — 最適化よりもアーキテクチャが重要
- **統合は難しい** — 後付けではなく、最初から設計に組み込む

何がうまくいき、何がうまくいかないかを見てきました。この基盤は、本番環境で数十年にわたって得た教訓を反映しています。

## 基盤がすべてを支える

PublishプラットフォームとSpatialプラットフォームの両方が、これらの機能を自動的に継承します：

| 機能 | Publish | Spatial |
|------------|---------|---------|
| オフライン編集 | インターネットなしでドキュメントを編集 | インターネットなしで3Dモデルを設計 |
| リアルタイム同期 | 複数の編集者、1つのドキュメント | 複数のデザイナー、1つのモデル |
| ユニバーサルデプロイ | あらゆるデバイスでフォーム | あらゆるデバイスで3Dビューアー |
| セルフホスト | あなたのドキュメントサーバー | あなたのデザインサーバー |
| クラウドオプション | マネージドまたはセルフマネージド | マネージドまたはセルフマネージド |

**プラットフォームを選べば、基盤は無料で付いてきます。**

## 技術詳細

アーキテクチャを評価しているチーム向け：

| レイヤー | テクノロジー |
|-------|------------|
| **ストレージ** | あらゆる場所でSQLite（ローカルデバイスとサーバー） |
| **同期エンジン** | NATS JetStreamによるCRDTベースのレプリケーション |
| **メッセージング** | NATS JetStream |
| **UIフレームワーク** | クロスプラットフォームのネイティブレンダリング |
| **API** | HTTP REST + SSE（Server-Sent Events） |
| **AI統合** | Model Context Protocol（MCP） |
| **認証** | OIDC互換、独自のIdPを持ち込み可能 |

### NATS JetStream

私たちのメッセージング基盤は、**CNCF（Cloud Native Computing Foundation）** のインキュベーションプロジェクトです。Kubernetesを統括しているのと同じ財団です。

| 項目 | 詳細 |
|----------|--------|
| **ガバナンス** | CNCFインキュベーションプロジェクト |
| **ライセンス** | Apache 2.0（100%オープンソース） |
| **認定** | SynadiaがSOC 2 Type IIを維持 |
| **コミュニティ** | 世界中で数千の本番デプロイメント |

オープンソース。エンタープライズ向けに強化。監査済み。

[セキュリティとコンプライアンスの詳細 →]({{< relref "/technology/security" >}})

### 分散SQLite

すべてのノード（あなたのノートPC、スマートフォン、サーバー）がSQLiteを実行します。変更はCRDTセマンティクスを用いてNATS JetStream経由でレプリケートされます。

- **どのサーバーが障害を起こしても** — 他のサーバーがサービスを継続
- **どのサーバーがオフラインになっても** — 再接続時に同期
- **単一障害点なし** — 真の分散アーキテクチャ
- **どこでも同じデータベース** — ローカルデバイスからグローバルクラスターまで

**標準技術。プロプライエタリなロックインなし。**

## 制限なくスケール

### 単一障害点（SPOF）なし

すべてのコンポーネントが冗長化されています。単一のサーバー、サービス、データセンターがシステム全体を停止させることはありません。どのノードが障害を起こしても、システムは稼働し続けます。

### 単一パフォーマンスポイント（SPOP）なし

計算処理は水平方向にスケールします。より大きなサーバーを購入するのではなく、ノードを追加することで容量を増やします。ワークロードは利用可能なリソース全体に自動的に分散されます。

### 数百のデータセンター

グローバル分散を前提に設計されたアーキテクチャ：

| 機能 | 意味 |
|------------|---------------|
| **どこにでもデプロイ** | クラウド、オンプレミス、エッジ、エアギャップ |
| **ユーザーの近くにデプロイ** | 低レイテンシ、地域のコンプライアンスに対応 |
| **冗長性のためにレプリケート** | リージョン障害を乗り切る |
| **分断耐性** | ネットワークが分断されても独立して稼働 |

### デプロイオプション

| 方法 | ユースケース |
|--------|----------|
| **バイナリ** | 単一ファイルでのデプロイ、最小限の依存関係 |
| **Docker** | コンテナ化された、再現可能な環境 |
| **Kubernetes** | オーケストレーションされた、オートスケーリングするクラスター |

**1台のノートPCから数百のデータセンターまで。同じアーキテクチャ。同じコードベース。**
