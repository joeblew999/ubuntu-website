## 1つのアーキテクチャで多様なビークルに対応

Ubuntu Software のフリートアーキテクチャは、**設計段階からビークル非依存**です。ドローンフリートを管理するのと同じ NATS JetStream インフラストラクチャ、デジタルツインパターン、認可モデルで、乗用車、トラック、自律走行地上車両も管理できます。

---

## 共通の要素

以下のコンポーネントは、すべてのビークルタイプで同じように動作します。

| コンポーネント | 説明 |
|-----------|-------------|
| **NATS JetStream** | メッセージング基盤。あらゆるテレメトリに対応 |
| **サブジェクト階層** | `fleet.{env}.veh.{id}.*` — ビークルIDは単なる識別子 |
| **デジタルツイン** | ステートストリーム、イベントストリーム、シャドウストア |
| **認可** | 分散型セキュリティ、権限付与、サードパーティアクセス |
| **ストリームとイベント** | テレメトリの集約、監査証跡、クエリ可能なステート |

**テレメトリをどのビークルが生成しているかは、アーキテクチャには関係ありません。** ドローンからの位置情報の更新も、トラックからの位置情報の更新も、同じインフラストラクチャを流れます。

---

## ビークル固有の要素

プラットフォームごとに固有の要件があります。

| 項目 | プラットフォームごとの違い |
|--------|-------------------|
| **ハードウェア** | 機体かシャーシか、フライトコントローラーか ECU か |
| **プロトコル** | MAVLink、CAN バス、ROS 2、J1939 |
| **安全モデル** | RC オーバーライドか非常停止か、RTL かその場停止か |
| **センサー** | 高度か最低地上高か、対気速度か車輪速度か |
| **規制** | 航空当局か道路交通当局か |

## ゲートウェイパターン

[ビークルゲートウェイ]({{< relref "/fleet/gateway" >}})は、ビークル固有のプロトコルと NATS を橋渡しします。プラットフォームごとにゲートウェイの実装があります。

```
┌─────────────────────────────────────────────────────────────────┐
│                     VEHICLE GATEWAY                              │
├─────────────────┬─────────────────┬─────────────────────────────┤
│   MAVLink GW    │    CAN GW       │      ROS 2 GW               │
│   (Drones)      │  (Cars/Trucks)  │   (ROS Robots)              │
└────────┬────────┴────────┬────────┴────────────┬────────────────┘
         │                 │                      │
         ▼                 ▼                      ▼
┌─────────────────────────────────────────────────────────────────┐
│                      NATS JETSTREAM                              │
│            Same subjects, same streams, same patterns            │
└─────────────────────────────────────────────────────────────────┘
```

ゲートウェイは次の役割を担います。
- プロトコル固有のメッセージを共通のテレメトリ形式に変換する
- 標準のサブジェクト階層にパブリッシュする
- 安全ポリシーを適用する
- 接続が途切れている間はストア・アンド・フォワードで処理する

## 新しいプラットフォームの追加

このアーキテクチャは、次の条件を満たすあらゆるビークルに対応します。

1. **テレメトリを生成できる** — 位置、速度、ヘルスデータ
2. **コマンドを受け付けられる** — 開始、停止、ウェイポイントナビゲーション
3. **ゲートウェイを実行できる** — ネイティブプロトコルを NATS に変換

カスタムプラットフォームは、自身のプロトコル用のゲートウェイを実装するだけで統合できます。それ以外のインフラストラクチャ（NATS、ストリーム、認可）は変更なしでそのまま使えます。
