## なぜ重要なのか

点検、マッピング、測量、公共安全などの商業運用でDJIドローンを飛ばしているなら、移行計画が必要です。既存のドローンが飛ばなくなるからではありません。理由は次のとおりです：

- 禁止措置後は**ファームウェア更新なし**
- 正規チャネルからの**スペアパーツ供給なし**
- カスタム統合のための**SDKサポートなし**
- フリート管理用の**クラウドサービスなし**
- フリート拡張のための**新規購入不可**

様子見を続ける事業者は、割高な価格で緊急移行を迫られることになります。今すぐ始める事業者は、計画的に移行できます。

## 現状

### 何が起きたのか

期限の前日にあたる2025年12月22日、FCCはDJIをCovered Listに追加すると発表しました。政権はNDAA第1709条で義務付けられたセキュリティ監査を経ずに、代わりに「国家安全保障上の判断」を発出しました。

DJIは2025年3月、6月、12月に、各機関に自社製品の調査を求める書簡を送付しました。どの機関も応答しませんでした。調査は開始されず、証拠も収集されませんでした。

議会は第1709条に意図的に落とし穴を設けていました。監査を実施する機関が指定されておらず、監査が行われなければ禁止が自動的に発効する仕組みだったのです。結果は最初から決まっていました。

### それが意味すること

| 影響 | 既存のDJIフリート | DJIの新規購入 |
|--------|------------------------|-------------------|
| **飛行** | FAA Part 107の下で引き続き合法 | 不可 |
| **ファームウェア** | 更新なし | 該当なし |
| **パーツ** | 限定的/グレーマーケット | 該当なし |
| **SDK/API** | サポート対象外 | 該当なし |
| **クラウドサービス** | 不透明 | 該当なし |
| **新モデル** | 該当なし | 不可 |

### 影響を受ける対象

- **政府機関** — すでにDJI製品の調達が制限されている
- **公共安全** — 米国の消防、警察、捜索救助（SAR）の80%以上がDJIを使用
- **商業事業者** — 点検、マッピング、測量、農業
- **エンタープライズフリート** — インフラ、公益事業、建設
- **防衛請負業者** — Blue UAS要件

## 移行パス

### 得られるもの

オープンソースへの移行は、単に禁止措置を回避するためだけのものではありません。次のものが得られます：

| DJI | オープンソース（PX4/ArduPilot） |
|-----|----------------------------|
| 閉鎖的なエコシステム | ベンダー非依存 |
| 独占的なデータ | 自分のデータを自分のサーバーで |
| 機能ロードマップは相手が管理 | コミュニティ + 自社のロードマップ |
| SDKの制約 | ソースコードへの完全アクセス |
| ハードウェアのロックイン | 複数のメーカー |
| クラウド依存 | セルフホストまたはマネージド |

### 対応プラットフォーム

オープンソースのフライトスタックは、幅広いハードウェアで動作します：

| プラットフォーム | フライトスタック | 強み |
|----------|-------------|-----------|
| **Holybro X500/S500** | PX4/ArduPilot | 実績があり、入手しやすく、ドキュメントが充実 |
| **カスタムビルド** | PX4/ArduPilot | 最大限の柔軟性 |
| **Freefly** | PX4 | プロ向けシネマ/測量 |
| **Autel** | 独自仕様 | 米国で組立、ただしNDAAの審査対象でもある |
| **Skydio** | 独自仕様 | 米国製、自律飛行に注力 |

フリート運用には、以下の理由からPX4ベースのプラットフォームを推奨します：
- 商業的な支援を受けたオープンソース（Dronecode Foundation）
- MAVLinkプロトコルはオープン標準
- 互換コンポーネントの大規模なエコシステム
- BSDライセンスにより独自の改変が可能

### 地上管制ソフトウェアの選択肢

| ソフトウェア | プロトコル | 強み |
|----------|----------|-----------|
| **QGroundControl** | MAVLink | 無料、クロスプラットフォーム、PX4/ArduPilot対応 |
| **Mission Planner** | MAVLink | ArduPilot中心、Windows |
| **UgCS** | MAVLink | 商用、高度なミッション計画 |
| **当社のフリートプラットフォーム** | NATS + MAVLink | 複数機体、エンタープライズ |

## 移行ティア

### ティア1：並行フリート（6〜12か月）

最適な対象：稼働中の運用があり、ダウンタイムのリスクを取れない機関。

1. **テスト機の調達** — まずは1〜3機のオープンソースプラットフォームから
2. **パイロットの訓練** — 送信機もソフトウェアも異なる
3. **ワークフローの検証** — マッピング、点検など、自社のユースケース
4. **SOPの策定** — 新しいチェックリスト、保守手順
5. **段階的な移行** — 信頼が高まるにつれて運用を移行

### ティア2：計画的移行（3〜6か月）

最適な対象：移行期間をスケジュールできる事業者。

1. **保有資産の評価** — どのDJI資産、どのワークフローが対象か
2. **プラットフォームの選定** — 機能をミッションのニーズに合わせる
3. **調達** — ハードウェアを発注し、リードタイムを確保
4. **集中訓練** — 短期集中のパイロット訓練
5. **切り替え** — DJI資産を計画的に退役させる

### ティア3：緊急移行（1〜3か月）

最適な対象：待ちすぎた事業者。

1. **即時調達** — 割高な価格、限られた選択肢
2. **短期集中訓練** — 集中的、場合によっては外部業者に委託
3. **能力の低下** — 一時的なワークフローの欠落を受け入れる
4. **反復改善** — 時間をかけて運用を改善

**ティア3にならないでください。**

## よくある質問

**既存のDJIドローンは使えなくなりますか？**

いいえ。現在のドローンはFAA Part 107の下で引き続き飛行できます。ただし、ファームウェア更新は受けられず、パーツが入手しにくくなる可能性があり、クラウドサービスが終了する可能性もあります。

**Autelは安全な代替手段ですか？**

AutelもNDAA第1709条の監査要件で名指しされています。DJIと同じスケジュールに直面しています。

**Skydioは安全な代替手段ですか？**

Skydioは米国製で、同じ制限の対象ではありません。ただし、そのエコシステムも独自仕様です。

**なぜ他の独自プラットフォームではなくオープンソースなのですか？**

オープンソースなら主導権を握れます。あるベンダーへの依存を、別のベンダーへの依存に置き換えるわけではありません。ソフトウェアは自由に改変でき、データは自分のものとして保持でき、ハードウェアは交換可能です。

**移行にはどのくらいの期間がかかりますか？**

運用内容によります。混乱を最小限に抑えた計画的な移行には3〜6か月を見込んでください。緊急移行は数週間で可能ですが、コストとリスクが高くなります。

**既存のマッピングワークフローはどうなりますか？**

ほとんどの処理ソフトウェア（Pix4D、DroneDeploy、ODM）は、ジオタグ付き画像を生成するドローンであれば機種を問わず動作します。移行が必要なのは撮影プラットフォームであり、処理バックエンドではありません。
