## 一种语言。每种输出。每种语言。

单一来源的内容管理系统。用一种 DSL 定义一切——**以文本（1D）驱动所有 2D 和 3D 输出**。组件可以层层包含其他组件。输出到任意渠道。自动翻译成任意语言。还能把数据回收采集回来。

全部支持 Web。全部全球可访问。品牌始终完美一致——靠的不是自律，而是架构。

---

## 问题所在

组织通过多个渠道发布内容：网站、PDF、电子邮件、表单、标牌。

每个渠道单独维护。内容逐渐偏离。品牌形象割裂。翻译滞后。表单提交需要手动重新录入。

**一处改动意味着要更新五个系统。要么干脆就没人更新。**

---

## 一种 DSL

一切都用同一种语言定义。

**文本内容：**
```
# Welcome to Our Service

We help organizations {industry} achieve {outcome}.
```

**图形：**
```
@logo: svg {
  viewBox: "0 0 200 50"
  rect: { x: 0, y: 0, width: 50, height: 50, fill: "#2563eb" }
  text: { x: 60, y: 35, content: "Ubuntu", font: "bold 24px" }
}
```

**表单字段：**
```
Name: [_______________]{field: name, required: true}
Email: [_______________]{field: email, type: email}
Date: [__/__/____]{field: date, type: date}
```

**电子邮件：**
```
@welcome-email: email {
  to: {customer.email}
  subject: "Welcome, {customer.name}"
  body: include welcome-content
}
```

**一种语言。文本、图形、表单、电子邮件、文档。**

---

## 组合

组件包含组件。

```
@header: compose {
  include: logo
  include: navigation
  include: search-bar
}

@page-template: compose {
  include: header
  include: content
  include: footer
}

@welcome-letter: compose {
  include: page-template
  content: "Dear {customer.name}, welcome to..."
}

@application-form: compose {
  include: page-template
  content: include form-fields
}
```

**级联效应：**
- 更换徽标 → 页眉随之更新
- 页眉更新 → 每个页面随之更新
- 每个页面更新 → 每个 PDF、电子邮件、表单随之更新

**这就是品牌始终保持完美一致的原因。** 不是因为有人记得去更新所有内容，而是因为架构让它不可能不更新。

链接到任何现有内容。在整个系统中复用。唯一可信来源。

## 输出

从一个来源，生成一切：

| 输出 | 效果 |
|--------|--------------|
| 网页 | 渲染为 HTML，SEO 就绪 |
| PDF | 可直接印刷，适合归档 |
| 电子邮件 | 直接发送给收件人 |
| Web 表单 | 交互式，数据回收采集 |
| PDF 表单 | 可在线填写或打印填写，通过 OCR 回收采集 |
| SVG 图形 | 矢量资源，任意尺寸 |
| 地图 | 可视化您的位置数据 |
| 信息亭 | 实体显示屏，实时更新 |

**每种输出都会自动翻译。**

用英语撰写。德国同事看到德语。西班牙合作伙伴看到西班牙语。日本客户看到日语。

不是事后翻译，而是在渲染过程中完成翻译。每种输出。每种语言。全部自动。

| 能力 | 含义 |

| 编辑器内实时翻译 | 跨语言同步协作 |

| 离线 AI | 无需联网即可工作 |
| 语境感知 | 能区分教育、法律、医疗等领域术语 |
| 双向 | 对方用自己的语言编辑，您看到的是您的语言 |

**一次撰写，以所有语言发布。**

## 采集

表单可以回收采集数据。因为表单是我们生成的，所以我们确切知道每个字段的位置。

| 渠道 | 效果 |
|---------|--------------|
| 提交 Web 表单 | 数据流入您的数据库 |
| 以数字方式填写 PDF 表单 | 数据提取到您的数据库 |
| 打印 PDF 表单、手写填写后扫描 | 通过 OCR 采集到您的数据库 |

无需训练 OCR。无需字段映射。表单是我们生成的——我们知道一切在哪里。

**纸质或数字，数据相同，去向相同。**

## 人在回路：实时现场作业

Publish 不仅仅用于静态文档，它还是现场人员与您的系统实时交互的方式。

### 全面接入的设备

每位现场人员的设备既是传感器，也是显示屏：

| 输入（来自现场） | 输出（发往现场） |
|--------------------|-------------------|
| GPS 位置 | 路线地图、逐向导航 |
| 语音命令（SST） | 任务通知 |
| 触控交互 | 日程更新 |
| 表单提交 | 确认提醒 |
| 摄像头（照片/视频） | 状态显示 |

系统知道每位工作人员的位置。工作人员也可以通过语音、触控或表单进行反馈。

### 2D 输出

Publish 渲染所有 2D 内容——网页、文档、地图、显示屏：

| 输出 | 用例 | 示例 |
|--------|----------|---------|
| **网页** | 客户门户、状态跟踪 | 服务状态、订单跟踪 |
| **路线地图** | 导航、配送跟踪 | 垃圾收运、配送站点 |
| **仪表板** | 状态概览、KPI | 调度控制台、团队绩效 |
| **文档** | 工单、报告、表单 | PDF 清单、合规导出 |
| **信息亭** | 公共显示屏、团队看板 | 场站状态、餐厅菜单 |

如需 **3D 空间可视化**——建筑工地、仓库、数字孪生——请参阅 [Spatial 平台](/platform/spatial/)。

### 语音驱动的更新

语音转文本（SST）支持免手动的系统交互：

| 工作人员说 | 系统执行 |
|-------------|-------------|
| "Main 街 123 号因施工封路" | 标记位置，重新规划路线 |
| "跳过下一个任务，客户不在" | 从队列中移除，调整日程 |
| "设备需要维修" | 创建维护工单 |
| "任务完成" | 记录完成情况，触发下一个工作流 |

无需打电话给调度。无需对讲机来回沟通。工作人员开口，AI 倾听，系统随之调整。

### 权限层级

人的判断优先于 AI 建议：

```

```

**AI 很强大——但身处现场、亲眼所见的人拥有最终决定权。**

### 在线状态与通知

人并非随时都有空。系统知道谁有空：

| 能力 | 作用 |
|------------|--------------|
| **在线状态跟踪** | 谁在线、谁离线、谁忙碌 |
| **角色感知** | 谁可以审批、谁可以否决、谁在值班 |
| **智能路由** | 通知优先发送给有空的人员 |
| **升级** | 如果主要负责人未响应，则升级至后备人员 |
| **确认** | 跟踪谁看到了什么、何时做出响应 |

**通知渠道：**

- 推送通知（移动端/桌面端）
- 关键警报使用短信
- 异步更新使用电子邮件
- 带声音/触觉反馈的应用内提醒
- 信息亭显示屏，便于团队查看

系统会根据人员的可用情况进行调整。紧急问题会找到合适的人。非紧急问题会排队等待，直到有人准备好处理。

### 离线韧性

现场作业往往发生在网络失效的地方。设备仍能继续工作：

- **连接中断** → 应用使用本地 SQLite 继续运行
- **更改在本地排队** → 重新连接后同步
- **数据零丢失** → Automerge CRDT 处理冲突
- **在线状态更新** → 标记为离线，通知进入队列

现场作业不能因网络问题而中断。这一架构确保它们不会中断。

## WellKnown 网关：数据主权

您发布的内容去了哪里？外部平台？这正是 **WellKnown 网关** 发挥作用的地方——即使向其他系统发布内容，也能确保数据归您所有。

### 平台锁定的问题

传统方式：
- 客户数据存放在 Salesforce
- 文档存放在 Google Drive
- 表单存放在 Typeform
- 您依赖于每个供应商的 API
- 一旦任何供应商更改条款、提价或停止服务——您就只能手忙脚乱

### WellKnown 解决方案

```
┌─────────────────────────────────────────────────────────────────┐
│                    YOUR DATA (Source of Truth)                   │
│                                                                  │
│   SQLite on every device + NATS JetStream persistence            │
│   You own it. It's on your infrastructure.                       │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                    WELLKNOWN GATEWAY                             │
│                                                                  │
│   Publishes TO external platforms                                │
│   Syncs FROM external platforms                                  │
│   You control what goes where                                    │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
                              │
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
   ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
   │   Google    │     │   Social    │     │  Industry   │
   │   Drive     │     │   Media     │     │  Platforms  │
   └─────────────┘     └─────────────┘     └─────────────┘
```

**核心原则：** 您向平台发布内容。数据不归它们所有——而归您所有。

### 客户关系主权

您的客户与您的品牌互动，而不是与供应商的品牌互动：

| 没有 WellKnown | 使用 WellKnown |
|-------------------|----------------|
| 客户登录供应商门户 | 客户登录您自己的门户 |
| 供应商掌握客户关系 | 您掌握客户关系 |
| 供应商拥有您的客户名单 | 您掌控客户数据 |
| 更换供应商 = 重新构建 | 更换供应商 = 重新连接网关 |

客户以为自己在和您打交道。事实也确实如此。底层管道完全不可见。

### 基于互联网标准构建

WellKnown 采用的标准，与支撑电子邮件、日历和联邦式社交网络的标准相同：

| 标准 | 用途 | 示例 |
|----------|---------|---------|
| **RFC 8615** | `/.well-known/` URI 发现 | `yourdomain.com/.well-known/...` |
| **WebFinger** | 账户/资源发现 | 跨域查找用户 |
| **OAuth Discovery** | 授权端点 | 安全的第三方访问 |
| **CalDAV/CardDAV** | 日历/联系人同步 | 适用于任何兼容的应用 |
| **ActivityPub** | 联邦协议 | 与任何系统互操作 |

**您的域名就是您的身份。** 就像电子邮件（`you@yourdomain.com`）一样，您的数据位于您掌控的 URI 上。基于标准的联邦机制意味着您可以连接任何兼容的系统——而不仅仅是我们的系统。

开放网络就是这样运作的。我们只是把它应用到了发布领域。

### 数据可移植性

一切都同步为您掌控的标准格式：

- **文档** → 您的 SQLite 数据库
- **表单** → 您的数据库表
- **媒体** → 您的存储
- **审计日志** → 您的合规记录

随时导出。随时迁移。永远不会被困住。

## 更宏大体系的一部分

Publish 是统一维度技术栈中的 **2D 层**——全部支持 Web，全球可访问。

### 1D → 2D → 3D 技术栈

```
┌─────────────────────────────────────────────────────────────────┐
│                    SINGLE SOURCE OF TRUTH                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   1D: TEXT (Markdown/DSL)                                        │
│       └── Content definition, structured data, semantic markup   │
│                          │                                       │
│                          ▼                                       │
│   2D: PUBLISH                                                    │
│       └── Web pages, documents, forms, maps, dashboards, kiosks  │
│                          │                                       │
│                          ▼                                       │
│   3D: SPATIAL                                                    │
│       └── CAD, digital twins, robotics, simulation               │
│                                                                  │
│   ALL LAYERS: Web-capable, globally accessible                   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

| 层 | 平台 | 负责内容 |
|-------|----------|-----------------|
| **1D** | DSL/Markdown | 文本内容、结构化定义、源头 |
| **2D** | Publish | Web、文档、表单、地图、信息亭、电子邮件 |
| **3D** | [Spatial](/platform/spatial/) | CAD、数字孪生、机器人、仿真 |
| **共享** | [Foundation](/platform/foundation/) | 离线同步、CRDT、NATS、部署 |

**一切都支持 Web。** 1D 文本驱动 2D 输出。2D 输出可以嵌入 3D 视图。3D 模型可以生成 2D 文档。全部可通过浏览器访问，全部保持同步，全部源自同一个可信来源。

### 它们如何协同工作

对于从事 3D 工作的组织——机器人、制造、建筑——Publish 提供文档层：

- 由 3D 模型生成的**技术图纸**
- 从装配体中提取的 **BOM（物料清单）**
- 带分步图示的**作业指导书**
- 与 CAD 修订版本关联的**合规表单**
- 结合 2D 检查清单 + 3D 上下文的**现场检查**

同一个可信来源。2D 与 3D 输出保持同步。全部可通过 Web 访问。
