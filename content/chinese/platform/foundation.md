## 为真实世界而构建

网络会中断。团队遍布各大洲。服务器归您所有。我们正是为这样的现实而构建。

我们的基础并不在于功能，而在于软件应当如何运作。离线优先。自主可控。通用部署。这些原则贯穿我们构建的一切。

---

## 离线优先架构

**无网也能工作。联网自动同步。数据永不丢失。**

真正的工作往往发生在 WiFi 信号很差的地方：建筑工地、工厂车间、政府大楼、医院病房、偏远办公室。我们的基础默认网络会断开，而不是默认始终在线。

### 工作原理

| 组件 | 功能 |
|-----------|--------------|
| **本地优先数据** | 您的数据首先存储在您的设备上，而不是远方的服务器上 |
| **Automerge CRDT** | 多人同时编辑时无冲突合并 |
| **后台同步** | 网络恢复后自动同步 |
| **离线队列** | 操作在本地排队，条件允许时执行 |

**没有加载转圈。没有“连接已断开”错误。只管工作。**

## 随处部署

**一套代码库。全平台覆盖。原生体验。**

同一个应用可以在浏览器、桌面端和移动设备上运行。不是三个独立的产品，而是一套可部署到任何地方的代码库。

### 支持的平台

| 平台 | 交付方式 |
|----------|----------|
| **Web** | 任何现代浏览器：Chrome、Firefox、Safari、Edge |
| **桌面端** | 适用于 Windows、macOS、Linux 的原生应用 |
| **移动端** | 适用于 iOS 和 Android 的原生应用 |

您的团队在办公室使用台式机。现场人员使用平板电脑。客户使用手机。所有人都访问同一个系统、同一份数据。

**一次编写。随处部署。只需维护一套代码库。**

**您的云。我们的云。不用云。由您选择。**

同步并不依赖我们的服务器。您可以连接到任何适合您组织的基础设施。

### 部署模式

| 模式 | 最适合 |
|-------|----------|
| **Ubuntu Software 云** | 设置最快，由我们负责运维 |

需要在不同模式之间切换？非常简单。无论数据存放在哪里，其格式都不会改变。

**没有供应商锁定。没有强制云依赖。真正的部署灵活性。**

## 自主可控

**您的数据。您的服务器。您的规则。**

自主可控意味着由您掌控自己的基础设施。不是“按我们的条款托管您的数据”，而是真正属于您。

### 自主可控意味着什么

- **随处运行**：您的数据中心、您的云账户、您的笔记本电脑
- **不回连**：软件无需联系我们的服务器即可运行
- **全部导出**：标准格式，数据完全可迁移
- **不跟踪使用情况**：我们看不到您用我们的软件做了什么
- **永久许可选项**：即使我们不复存在，软件也能继续运行

**这不仅关乎隐私，更关乎运营独立。**

## Wellknown 网关

**发布到大型科技平台。掌握用户关系。**

网络的各大门户（Google、Apple、YouTube）拥有巨大的覆盖面。但向它们发布内容，并不意味着被它们掌控。

### 扭转关系

传统方式：
```
User → YouTube (owns everything) → Your content (captive)
```

Wellknown 方式：
```
User → Your Gateway → Your System (primary)
                   ↳→ YouTube (mirror for discovery)
```

**由您掌控入口。** 大型科技平台成为可选的分发渠道，而不是牢笼。

### 工作原理

| 能力 | 含义 |
|------------|---------------|
| **处处使用您的 URI** | 链接指向您的网关，而不是他们的 |
| **智能路由** | 将 iOS 用户引导至 Apple，Android 用户引导至 Google，Web 用户引导至您的播放器 |
| **镜像发布** | 自动将副本发布到 YouTube、Google 地图、Apple 日历 |
| **自有分析数据** | 看到全部数据，追踪每位用户，无需共享数据 |
| **内置退出策略** | 从路由中移除任何平台都不会导致链接失效 |

### 兼容一切

- **视频**：托管在您的服务器上，镜像到 YouTube/Twitch 以扩大覆盖面
- **日历**：您的 CalDAV 服务器，同步到 Google/Apple 以便使用
- **地图**：您的地理数据，与 Google/Apple 地图集成
- **邮件**：您的邮件服务器，与 Gmail 兼容
- **文件**：您的存储，选择性共享到 Drive/Dropbox

**发布到他们的平台。永远不被锁定在其中。**

## 25 年企业级经验

**Ubuntu Software 创立于 1999 年。** 我们历经互联网泡沫、移动革命、云转型和 AI 兴起，一直在构建企业系统。

### 经验教会我们的

- **供应商会消失**：从第一天起就为数据可迁移性而构建
- **网络会故障**：离线优先不是可选项，而是必需品
- **需求会变化**：开放标准比专有格式更长久
- **规模会出乎意料**：架构比优化更重要
- **集成很难**：要从设计之初就考虑集成，而不是事后硬加

我们见识过哪些方法有效、哪些无效。这一基础凝聚了数十年在生产环境中积累的经验教训。

## 技术细节

供评估我们架构的团队参考：

| 层 | 技术 |
|-------|------------|
| **存储** | 处处使用 SQLite，涵盖本地设备和服务器 |
| **同步引擎** | 基于 CRDT 的复制，通过 NATS JetStream 实现 |
| **消息传递** | NATS JetStream |
| **UI 框架** | 跨平台原生渲染 |
| **API** | HTTP REST + SSE（服务器发送事件） |
| **AI 集成** | 模型上下文协议（MCP） |
| **认证** | 兼容 OIDC，可使用您自己的 IdP |

### NATS JetStream

我们的消息传递骨干是 **CNCF（云原生计算基金会）** 的孵化项目，与管理 Kubernetes 的是同一个基金会。

| 属性 | 详情 |
|----------|--------|
| **治理** | CNCF 孵化项目 |
| **许可证** | Apache 2.0（100% 开源） |
| **认证** | Synadia 持有 SOC 2 Type II 认证 |
| **社区** | 全球数千个生产部署 |

开源。经过企业级加固。经过审计。

[安全与合规详情 →]({{< relref "/technology/security" >}})

### 分布式 SQLite

每个节点（您的笔记本电脑、您的手机、您的服务器）都运行 SQLite。更改通过 NATS JetStream 以 CRDT 语义进行复制。

- **任何服务器都可能故障**：其他服务器继续提供服务
- **任何服务器都可能离线**：重新连接后同步
- **没有单点故障**：真正的分布式架构
- **处处使用同一个数据库**：从本地设备到全球集群

**标准技术。没有专有锁定。**

## 无限扩展

### 无单点故障（SPOF）

每个组件都有冗余。任何单一服务器、服务或数据中心都不会导致整个系统瘫痪。任意节点发生故障，系统依然正常运行。

### 无单点性能瓶颈（SPOP）

计算能力可横向扩展。通过增加节点来提升容量，而不是购买更大的服务器。工作负载会自动分布到可用资源上。

### 数百个数据中心

专为全球分布而设计的架构：

| 能力 | 含义 |
|------------|---------------|
| **随处部署** | 云端、本地、边缘、物理隔离环境 |
| **靠近用户部署** | 低延迟，满足本地合规要求 |
| **复制以实现冗余** | 抵御区域性中断 |
| **分区容错** | 网络分裂时可独立运行 |

### 部署选项

| 方式 | 使用场景 |
|--------|----------|
| **二进制文件** | 单文件部署，依赖极少 |
| **Docker** | 容器化、可复现的环境 |
| **Kubernetes** | 编排式、自动扩缩容的集群 |

**从一台笔记本电脑到数百个数据中心。同样的架构。同一套代码库。**
