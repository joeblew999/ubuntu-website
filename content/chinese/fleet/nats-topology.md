## 面向车队规模的 NATS 架构

消息拓扑决定了遥测数据如何流动、状态在何处持久化，以及连接质量下降时系统的行为方式。该架构可从数十辆扩展到数千辆载具，同时保持低延迟和高可靠性。

---

## 挑战

车队消息系统必须满足相互冲突的需求：

| 需求 | 挑战 |
|-------------|-----------|
| **低延迟** | 载具间通信需要毫秒级而非秒级响应 |
| **广域网弹性** | 蜂窝连接会中断，延迟会突增，带宽会波动 |
| **状态持久化** | 数字孪生数据必须在重启和重新连接后得以保留 |
| **规模** | 数千个并发的发布者和订阅者 |
| **隔离** | 单个载具的故障不应级联影响整个车队 |

传统架构不得不做出取舍。集中式代理会增加延迟。点对点网状网络无法扩展。纯边缘方案则会失去车队全局可见性。

---

## 第 1 层：载具叶节点

每架无人机都在 Jetson 上运行一个 **NATS 叶节点**：

| 方面 | 配置 |
|--------|---------------|
| **进程** | 以叶节点模式运行的 nats-server |
| **存储** | 位于 SSD/eMMC 上的本地 JetStream |
| **连接** | 单一上游连接至区域枢纽 |
| **资源** | 约 50MB 内存，CPU 占用极低 |

**叶节点提供的能力：**

### 本地发布/订阅

载具上的各项服务通过本地 NATS 实例进行通信：

```
Vehicle Gateway ──publish──▶ fleet.prod.veh.VID-001.state.position
                                       │
                                       ▼
                            ┌──────────────────┐
                            │   Local NATS     │
                            │   (Leaf Node)    │
                            └──────────────────┘
                                       │
                                       ▼
AI Perception ◀──subscribe── fleet.prod.veh.VID-001.state.position
```

载具上服务之间的消息永远不会离开载具。延迟低于一毫秒。

### 存储转发

当上游连接中断时，叶节点会：

1. 继续接受来自本地服务的发布
2. 将消息存储在本地 JetStream 中
3. 将发往枢纽的出站消息排入队列
4. 在连接恢复后重新连接并重放消息

这意味着**载具在连接中断期间仍可继续运行**。链路恢复后状态会自动同步。

### 广域网隔离

叶节点充当载具与广域网之间的缓冲层：

- **背压** — 如果枢纽处理不过来，叶节点会在本地进行缓冲
- **过滤** — 只有已订阅的主题才会经由广域网链路传输
- **压缩** — NATS 协议具有高效的压缩能力
- **重新连接** — 采用指数退避的自动重新连接

## 第 2 层：区域枢纽集群

区域枢纽按地理区域汇聚载具：

| 方面 | 配置 |
|--------|---------------|
| **部署** | 3 节点 NATS 集群（最低要求） |
| **位置** | 云区域或边缘数据中心 |
| **存储** | 位于高速 SSD 上的 JetStream |
| **容量** | 每个集群可承载数百个叶节点连接 |

**为何按区域部署：**

- **延迟** — 叶节点连接到就近的枢纽
- **带宽** — 遥测数据默认保留在区域内
- **合规** — 满足数据驻留要求
- **故障隔离** — 某一区域的故障不会影响其他区域

**枢纽职责：**

| 功能 | 描述 |
|----------|-------------|
| **叶节点汇聚** | 接受来自载具叶节点的连接 |
| **流存储** | 在 JetStream 中持久化数字孪生数据 |
| **消费者支持** | 为车队仪表板、API 和分析提供服务 |
| **跨区域路由** | 在需要时转发至全局层 |

### 集群配置

3 节点集群可提供：

- **高可用性** — 可在单节点故障时继续运行
- **数据复制** — JetStream 流在各节点间复制
- **负载分配** — 叶节点连接在各节点间均衡分布

```yaml
# Example hub cluster configuration
cluster:
  name: hub-americas
  routes:
    - nats://hub-americas-1:6222
    - nats://hub-americas-2:6222
    - nats://hub-americas-3:6222

jetstream:
  store_dir: /data/jetstream
  max_memory_store: 4GB
  max_file_store: 100GB

leafnodes:
  port: 7422
  authorization:
    users:
      - user: vehicle
        password: $VEHICLE_PASSWORD
        allowed_connection_types: ["LEAFNODE"]
```

## 第 3 层：全局层（可选）

对于跨越多个区域的车队，全局层可实现：

| 功能 | 描述 |
|----------|-------------|
| **跨区域镜像** | 在区域枢纽之间复制流 |
| **全局汇聚** | 车队范围的仪表板和分析 |
| **命令路由** | 向任意区域的载具发送命令 |
| **灾难恢复** | 区域间故障转移 |

**实现方案：**

1. **NATS 超级集群** — 通过网关连接将各区域集群联合起来
2. **JetStream 镜像** — 将特定流复制到中心位置
3. **应用层方案** — 在区域 API 之间进行自定义同步

大多数车队在单一区域内运营，初期无需全局层。

## 该拓扑的优势

### 低延迟本地发布/订阅

载具上的通信延迟**低于一毫秒**：

```
MAVLink message received
    └─▶ Vehicle Gateway publishes to local NATS
        └─▶ AI Perception subscribes from local NATS
            └─▶ Total latency: <1ms
```

载具上的通信无需经过广域网往返。

### 广域网隔离

载具运行**在连接中断期间仍可继续**：

- 感知系统保持运行
- 状态在本地累积
- 命令排队等待执行
- 重新连接后自动同步

### 车队范围的数字孪生回放

JetStream 支持跨整个车队的**时间维度查询**：

```
# Replay vehicle state from 10 minutes ago
nats stream get TWIN_STATE --start-time="2024-01-15T10:00:00Z"

# Subscribe to real-time state updates
nats sub "fleet.prod.veh.*.state.position"
```

每辆载具的状态历史都可以从区域枢纽查询。

### 可扩展架构

该拓扑支持水平扩展：

| 扩展点 | 方法 |
|-------------|----------|
| **更多载具** | 向现有枢纽添加叶节点连接 |
| **更高吞吐量** | 向枢纽集群添加节点 |
| **更多区域** | 部署额外的区域枢纽 |
| **全球覆盖** | 通过超级集群连接各枢纽 |

## 连接流程

载具通电时：

```
1. Jetson boots, NATS leaf node starts
2. Leaf node reads hub address from config
3. TLS connection established to regional hub
4. Authentication via credentials
5. Leaf node advertises local subjects
6. Hub routes relevant subscriptions to leaf
7. Bidirectional message flow begins
```

连接中断时：

```
1. Leaf node detects connection loss
2. Local pub/sub continues uninterrupted
3. Outbound messages queue locally
4. Reconnection attempts with backoff
5. On reconnect, queued messages replay
6. Stream state synchronizes
```

## 安全性

每个连接都经过身份验证和加密：

| 连接 | 安全措施 |
|------------|----------|
| **叶节点 → 枢纽** | TLS 1.3，凭证认证 |
| **枢纽集群** | TLS，集群路由经过认证 |
| **枢纽 → 全局** | TLS，网关认证 |

凭证按载具单独签发，从而支持：

- 撤销单个载具的访问权限
- 按载具记录审计轨迹
- 按连接进行速率限制

授权模型支持**基于授权许可的去中心化安全机制**——第三方无需中心协调即可获得限定范围、限定时间的访问权限。有关凭证管理和第三方集成的详细信息，请参阅 [授权与许可]({{< relref "/fleet/authorization" >}})。

## 总结

| 层级 | 用途 | 部署位置 |
|------|---------|------------|
| **叶节点（载具）** | 本地发布/订阅、存储转发 | Jetson 上 |
| **枢纽（区域）** | 汇聚、持久化、消费者 | 云/边缘数据中心 |
| **全局（可选）** | 跨区域、车队范围视图 | 中心云 |

该拓扑确保载具能够独立运行，同时保持车队范围的可见性与控制能力。
