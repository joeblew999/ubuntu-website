## 地上車両フリート向けハードウェア

地上車両（乗用車、トラック、AGV、自律走行プラットフォーム）は、ドローンと同じフリートアーキテクチャを使用します。ただし、ハードウェア、プロトコル、安全モデルは車両に適したものを採用します。

---

## プロトコルの選択肢

地上車両は業界標準のプロトコルで通信します：

### CAN バス

| 項目 | 詳細 |
|--------|---------|
| **規格** | CAN 2.0B / CAN FD |
| **データレート** | 500kbps (CAN) / 5Mbps (CAN FD) |
| **メッセージ形式** | DBC ファイルで信号のエンコーディングを定義 |
| **物理層** | 差動ペア、ノイズの多い環境でも堅牢 |

**CAN バスが提供する機能：**
- 車両システム（エンジン、トランスミッション、ブレーキ）への直接アクセス
- リアルタイムテレメトリ（速度、RPM、燃料、温度）
- 故障診断コード（OBD-II / J1939）
- アフターマーケットデバイスの統合

### J1939（大型車両）

トラック、バス、重機向け：

| 項目 | 詳細 |
|--------|---------|
| **規格** | SAE J1939 |
| **トランスポート** | CAN 2.0B（250kbps） |
| **アドレッシング** | PGN/SPN を含む 29 ビット識別子 |
| **用途** | エンジン、トランスミッション、ブレーキ、トレーラー |

**J1939 が提供する機能：**
- メーカーをまたいで標準化されたパラメータグループ（PGN）
- フリート全体で一貫したテレメトリ
- テレマティクスプラットフォームとの統合
- 規制要件への準拠

### ROS 2（自律走行プラットフォーム）

専用設計の自律走行車両向け：

| 項目 | 詳細 |
|--------|---------|
| **ミドルウェア** | ROS 2 Humble / Iron |
| **トランスポート** | DDS (Cyclone DDS, Fast DDS) |
| **メッセージタイプ** | 標準 (sensor_msgs, geometry_msgs) + カスタム |
| **QoS** | 信頼性・耐久性を設定可能 |

**ROS 2 が提供する機能：**
- ネイティブなセンサー統合（LiDAR、カメラ、IMU）
- ロボティクス向けの標準メッセージタイプ
- NATS への直接のトピックブリッジ
- シミュレーションとの互換性（Gazebo、CARLA）

## ハードウェアスタック

### コンピュートプラットフォーム

地上車両では通常、堅牢化された産業用コンピュータを使用します：

| プラットフォーム | ユースケース | 備考 |
|----------|----------|-------|
| **NVIDIA Jetson AGX Orin** | 自律走行車両 | 高性能な認識処理 |
| **NVIDIA Jetson Orin NX** | フリート車両 | 性能とコストのバランス |
| **産業用 PC** | テレマティクス専用 | 低コスト、GPU 不要 |
| **Neousys** | 堅牢な車載用途 | 広い動作温度範囲、イグニッション制御 |

**コンピュートの役割：**
- Vehicle Gateway（CAN/ROS 2 から NATS へ）
- NATS リーフノード
- エッジ AI 推論（オプション）
- 接続断時のストア・アンド・フォワード

### CAN インターフェース

| デバイス | インターフェース | 備考 |
|--------|-----------|-------|
| **PEAK PCAN-USB** | USB | 広く使われており、サポートも充実 |
| **Kvaser Leaf Light** | USB | 産業グレード |
| **SocketCAN 対応デバイス** | USB/PCIe | Linux ネイティブサポート |
| **Jetson ネイティブ CAN** | 内蔵 | AGX Orin で利用可能 |

### 通信接続

| 方式 | ユースケース |
|--------|----------|
| **4G/5G セルラー** | フリートの主要な接続手段 |
| **WiFi** | デポ/施設での運用 |
| **イーサネット** | ドックでの有線接続 |
| **衛星** | 遠隔地/地方での運用 |

## 車両タイプ

### 乗用車

| コンポーネント | 一般的な選択 |
|-----------|-------------------|
| **プロトコル** | CAN バス（OBD-II ポートまたは直接接続） |
| **コンピュート** | Jetson Orin NX または産業用 PC |
| **電源** | 12V 車両電源システム |
| **通信接続** | 4G/5G セルラー |
| **安全性** | ドライバーによるオーバーライド、緊急停止 |

**ユースケース：** ライドシェアフリート、レンタカー、配送車両

### 商用車（トラック）

| コンポーネント | 一般的な選択 |
|-----------|-------------------|
| **プロトコル** | J1939（CAN ベース） |
| **コンピュート** | 堅牢化された産業用 PC または Jetson |
| **電源** | 12V/24V 車両電源システム |
| **通信接続** | 4G/5G + 衛星バックアップ |
| **安全性** | ドライバーによるオーバーライド、ELD 準拠 |

**ユースケース：** 長距離物流、配送フリート、サービス車両

### 自律走行地上車両（AGV）

| コンポーネント | 一般的な選択 |
|-----------|-------------------|
| **プロトコル** | ROS 2 ネイティブまたは独自プロトコル |
| **コンピュート** | Jetson AGX Orin |
| **電源** | 24V/48V バッテリーシステム |
| **通信接続** | WiFi（施設内）+ セルラー（屋外） |
| **安全性** | 緊急停止、安全規格対応センサー |

**ユースケース：** 倉庫物流、鉱業、農業、港湾業務

## 安全モデル

地上車両の安全対策はドローンとは異なりますが、同じ原則に従います：

### 権限階層

```
Manual Override (highest authority)
    │
    ├── Steering wheel / brake pedal (driver present)
    ├── E-stop button (AGVs)
    └── Remote operator console
    │
    ▼
Autonomous System (software control)
    │
    ├── Perception → Planning → Control
    └── Geofencing, speed limits, operational domain
    │
    ▼
Fleet Management (lowest authority)
    │
    └── Mission assignment, routing, monitoring
```

### フェイルセーフ動作

| トリガー | ドローンでの対応 | 地上車両での対応 |
|---------|------------------|------------------------|
| 通信喪失 | 離陸地点への帰還（Return-to-Launch） | その場で停止 / 路肩に停車 |
| センサー故障 | 即時着陸 | 安全に停止し、オペレーターに通知 |
| ジオフェンス逸脱 | 境界内へ戻る | 境界で停止 |
| 緊急停止の作動 | モーター停止 | 即時ブレーキ |
| バッテリー残量低下 | RTL / 着陸 | デポへ帰還 / 安全に停止 |

### ネットワークの安全性

**ドローンと同じ原則：** NATS が制御ループに入ることはありません。

| NATS が行うこと | NATS が行わないこと |
|----------------|---------------------|
| テレメトリ収集 | リアルタイムのステアリング |
| ミッション割り当て | ブレーキコマンド |
| フリート連携 | スロットル制御 |
| 監視とアラート | セーフティクリティカルな判断 |

セーフティクリティカルな機能は、すべて車両のオンボードシステムが担います。ネットワークが切断されても失われるのは監視機能だけで、車両の制御は失われません。

## ゲートウェイの実装

Vehicle Gateway は、車両ネイティブのプロトコルと NATS をブリッジします：

```
┌─────────────────────────────────────────────────────────────────┐
│                    GROUND VEHICLE GATEWAY                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   CAN Bus ─────► DBC Parser ─────► Telemetry Subjects           │
│                                                                  │
│   J1939 ───────► PGN Decoder ────► Telemetry Subjects           │
│                                                                  │
│   ROS 2 ───────► Topic Bridge ───► Telemetry Subjects           │
│                                                                  │
│   Commands ◄───────────────────── Command Subjects              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                      NATS JETSTREAM                              │
│   fleet.prod.veh.{vehicle_id}.state.*                           │
│   fleet.prod.veh.{vehicle_id}.evt.*                             │
│   fleet.prod.veh.{vehicle_id}.cmd.*                             │
└─────────────────────────────────────────────────────────────────┘
```

**ゲートウェイの役割：**
- プロトコル変換（CAN/J1939/ROS 2 → 共通テレメトリ形式）
- 状態のダウンサンプリング（高頻度の CAN データを扱いやすいレートに削減）
- イベント抽出（状態変化やしきい値の検出）
- コマンド検証（実行前の安全チェック）
- ストア・アンド・フォワード（接続断時のバッファリング）

## サブジェクトマッピング

地上車両はドローンと同じサブジェクト階層を使用します：

| サブジェクト | 地上車両での内容 |
|---------|----------------------|
| `fleet.prod.veh.{id}.state.pos` | GPS 位置、方位 |
| `fleet.prod.veh.{id}.state.vel` | 速度、加速度 |
| `fleet.prod.veh.{id}.state.health` | エンジン状態、診断情報 |
| `fleet.prod.veh.{id}.state.fuel` | 燃料残量 / バッテリー SOC |
| `fleet.prod.veh.{id}.evt.trip` | トリップの開始/終了イベント |
| `fleet.prod.veh.{id}.evt.geofence` | ゾーンへの進入/退出 |
| `fleet.prod.veh.{id}.cmd.mission` | ルート割り当て |

サブジェクト構造は車両の種類に依存しません。ドローンとトラックが混在するフリートでも、まったく同じパターンを使用します。

## 統合パターン

### ELD 準拠（米国のトラック）

電子ログ記録装置（ELD）の要件：
- 運転時間（Hours of Service）の記録
- ドライバーの識別
- 位置の記録
- 当局へのデータ送信

ゲートウェイは J1939 のエンジンデータを取得し、ELD 準拠システムと統合します。

### テレマティクス統合

既存のテレマティクスプラットフォームは、次の方法で接続できます：
- NATS グラント（特定の車両をサブスクライブ）
- REST API（履歴データのクエリ）
- Webhook イベント（リアルタイムアラート）

### フリート管理システム

エンタープライズ向け TMS/FMS との統合：
- 車両の割り当て
- ルート最適化
- 燃料管理
- メンテナンス計画
