一家餐厅更新了菜单。接下来会发生什么？

有人修改网站。另一个人更新外卖菜单的 PDF。第三个人修改收银系统。最后，终于有人想起了数字菜单屏，再手动把它们也更新一遍。

四个系统。四次出错的机会。四个价格可能不一致的地方。

**这太荒谬了。而且这种情况随处可见。**

## 显示碎片化问题

走进任何一家需要对外展示信息的机构：

**餐厅**：菜单屏、餐桌二维码、网站、外卖平台、纸质菜单
**政府办事处**：排队叫号屏、导视标识、表格领取柜台、网站
**医疗机构**：候诊室显示屏、自助签到机、患者门户、纸质资料
**零售**：价格显示、促销标牌、库存状态、电子商务

每块显示屏通常都运行着各自的系统。每个都需要单独更新。每个都可能显示不同的信息。

**信息逐渐不一致。顾客感到困惑。员工把时间浪费在手动同步上。**

## 单一来源解决方案

如果每块显示屏——无论实体还是数字——都从同一个来源获取数据，会怎样？

```
Your Database (single source of truth)
         ↓
    Publish Engine
         ↓
┌────────┼────────┐
↓        ↓        ↓
Website  PDF    Kiosk Display
         ↓        ↓
      Print    Menu Board
```

价格只改一次。所有显示屏随之更新。

新菜品只添加一次。它会出现在所有地方。

售罄只标记一次。顾客立即就能看到——在网站上、菜单屏上，以及扫二维码打开的菜单上。

## 实时、可离线运行的自助终端

接下来才是有意思的部分。

传统数字标牌需要持续联网。网络断了？显示屏就会黑屏或显示过时的数据。

我们的方案使用树莓派设备，运行与其他所有系统相同的离线优先架构：

- **本地数据副本**：每台自助终端都保存一份相关数据的完整副本
- **Automerge 同步**：联网时自动同步更新
- **优雅降级**：网络中断？显示屏继续使用本地数据正常工作
- **变更队列**：在自助终端上所做的更新会在网络恢复后同步回去

**断网时依然能工作的菜单屏。离线时也能把提交内容排队保存的签到终端。**

## 切实可行的应用场景

### 餐厅系统

一个来源驱动：
- 数字菜单屏（实时价格，售罄菜品置灰）
- 二维码菜单（相同内容，针对手机优化）
- 网站菜单页面
- 用于打印的 PDF 菜单
- 后厨显示系统集成

修改一款汉堡的价格。所有地方随之更新。柜台旁的菜单屏、有人为餐饮外包打印的 PDF、网站——全部保持一致。

### 政府服务中心

一个来源驱动：
- 排队管理显示屏（"请 B-47 号办理"）
- 服务指南自助终端
- 可下载（PDF）或在线填写（网页/自助终端）的表格
- 导视标识
- 网站服务列表

更新办公时间。每块显示屏都会反映这一变化。导视终端、网站、纸质宣传单——全部正确。

### 医疗候诊室

一个来源驱动：
- 自助签到机（填写表格、加入排队）
- 等候时间显示屏
- 患者信息屏
- 纸质登记表（相同字段，一致版式）

患者在自助终端上填写表格 → 数据流入您的电子病历系统 → 无需人工转录。

### 零售环境

一个来源驱动：
- 价格显示（电子价签）
- 促销标牌
- 库存状态屏
- 网站商品列表
- 纸质商品目录

在库存系统中将商品标记为"清仓"。价格显示随之更新。网站随之更新。每周纸质广告显示清仓价格。

## 硬件方案

为什么选择树莓派？

**成本**：每个显示节点不到 100 美元，包括树莓派和基础外壳
**可靠性**：没有活动部件，运行 Linux，可连续运行多年
**灵活性**：HDMI 输出可驱动任意尺寸的显示屏
**可离线运行**：本地计算和存储，实现真正的边缘运行
**可更新**：远程管理软件更新

餐厅部署菜单屏的成本只是传统数字标牌的一小部分。政府办事处无需签订企业级标牌合同即可增加自助终端。

## 技术架构

每台自助终端运行：

| 组件 | 用途 |
|-----------|---------|
| **本地数据库** | 相关数据的 SQLite 副本 |
| **同步引擎** | Automerge CRDT，实现无冲突更新 |
| **显示渲染器** | Web 技术（HTML/CSS/JS），实现灵活布局 |
| **输入处理** | 触摸屏、键盘、条码扫描器、读卡器 |
| **离线队列** | 提交内容在本地存储，直至同步 |

运行网页表单的同一套代码库也运行在自助终端上。相同的校验。相同的字段布局。相同的数据去向。

## 不止于显示：还有输入设备

自助终端不仅是输出设备，也是输入点。

**表格填写**：顾客在自助终端触摸屏上填写表格
**文档扫描**：自助终端扫描纸质文件，由 OCR 提取数据
**支付处理**：集成读卡器
**身份验证**：用于扫描证件的摄像头
**签名采集**：触摸签名板

所有采集的数据与网页提交的数据走同一套系统。

一份政府表格可以通过以下方式提交：
- 网站网页表单 → 数据库
- 打印 PDF、填写后在自助终端扫描 → 数据库
- 自助终端触摸屏表单 → 数据库

**相同的数据。相同的去向。不同的输入方式。**

## 一致性的优势

"一致"的真正含义是：

顾客在您的网站上看到一份表格。同一位顾客来到您的办公室，在自助终端上看到同一份表格。相同的字段、相同的布局、相同的问题。

他们在自助终端上开始填写，时间不够了，扫描二维码在手机上继续填写。同一份表格，同样的进度（通过其会话同步）。

他们在家中填完，点击提交。数据流入您的数据库。无需重复录入，没有转录错误，没有字段名称错位。

**这就是单一来源发布延伸到实体显示屏后所能实现的。**

## 商业价值

**采用单一来源显示之前：**
- 员工花时间更新多个系统
- 信息不一致导致错误
- 顾客困惑（"标牌上是一个价格，网站上是另一个价格"）
- 传统数字标牌系统成本高昂
- 网络一断，显示屏就失灵

**采用单一来源显示之后：**
- 更新一次，处处生效
- 所有触点的信息保证一致
- 顾客投诉减少
- 通用硬件，通用价格
- 显示屏可离线工作

**账很好算：更少的错误、更少的员工时间、更好的顾客体验。**
