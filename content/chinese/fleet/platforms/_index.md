## 一个架构，多种载具

Ubuntu Software 车队架构**在设计上与载具类型无关**。管理无人机机队的 NATS JetStream 基础设施、数字孪生模式和授权模型，同样可以管理汽车、卡车和自动驾驶地面车辆。

---

## 通用部分

以下组件在所有载具类型上的工作方式完全相同：

| 组件 | 描述 |
|-----------|-------------|
| **NATS JetStream** | 消息传递骨干，适用于任何遥测数据 |
| **主题层级** | `fleet.{env}.veh.{id}.*` — 载具 ID 只是一个标识符 |
| **数字孪生** | 状态流、事件流、影子存储 |
| **授权** | 去中心化安全、授权许可、第三方访问 |
| **流与事件** | 遥测汇总、审计追踪、可查询状态 |

**架构并不关心遥测数据由谁产生。**来自无人机的位置更新与来自卡车的位置更新，都通过同一套基础设施流转。

---

## 载具特定部分

每个平台都有其独特的需求：

| 方面 | 因平台而异 |
|--------|-------------------|
| **硬件** | 机身与底盘、飞行控制器与 ECU |
| **协议** | MAVLink、CAN 总线、ROS 2、J1939 |
| **安全模型** | 遥控接管与紧急停止、返航（RTL）与原地停止 |
| **传感器** | 高度与离地间隙、空速与轮速 |
| **法规** | 航空管理机构与道路交通管理机构 |

## 网关模式

[载具网关]({{< relref "/fleet/gateway" >}})将载具原生协议桥接到 NATS。每个平台都有一个网关实现：

```
┌─────────────────────────────────────────────────────────────────┐
│                     VEHICLE GATEWAY                              │
├─────────────────┬─────────────────┬─────────────────────────────┤
│   MAVLink GW    │    CAN GW       │      ROS 2 GW               │
│   (Drones)      │  (Cars/Trucks)  │   (ROS Robots)              │
└────────┬────────┴────────┬────────┴────────────┬────────────────┘
         │                 │                      │
         ▼                 ▼                      ▼
┌─────────────────────────────────────────────────────────────────┐
│                      NATS JETSTREAM                              │
│            Same subjects, same streams, same patterns            │
└─────────────────────────────────────────────────────────────────┘
```

网关负责：
- 将特定协议的消息转换为通用遥测格式
- 发布到标准主题层级
- 执行安全策略
- 在连接中断期间处理存储转发

## 添加新平台

该架构支持任何能够满足以下条件的载具：

1. **生成遥测数据** — 位置、速度、健康状态数据
2. **接收指令** — 启动、停止、航点导航
3. **运行网关** — 将原生协议转换为 NATS

自定义平台通过为其协议实现网关来完成集成。其余基础设施（NATS、流、授权）无需任何改动即可工作。
