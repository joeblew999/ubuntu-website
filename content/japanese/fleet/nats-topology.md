## フリート規模のためのNATSアーキテクチャ

メッセージングトポロジーは、テレメトリの流れ方、状態の永続化先、そして接続性が低下した際のシステムの振る舞いを決定します。このアーキテクチャは、低レイテンシと高い信頼性を維持しながら、数十台から数千台の車両までスケールします。

---

## 課題

フリートメッセージングは、相反する要件を同時に満たす必要があります。

| 要件 | 課題 |
|-------------|-----------|
| **低レイテンシ** | 車両間通信には秒単位ではなくミリ秒単位の応答が必要 |
| **WAN耐障害性** | セルラー接続は切断され、レイテンシは急上昇し、帯域幅は変動する |
| **状態の永続化** | デジタルツインのデータは再起動や再接続後も保持されなければならない |
| **スケール** | 数千の同時パブリッシャーとサブスクライバー |
| **分離** | 車両の障害がフリート全体に波及してはならない |

従来のアーキテクチャではトレードオフが避けられません。集中型ブローカーはレイテンシを増加させます。ピアツーピアメッシュはスケールしません。エッジのみのアプローチではフリート全体の可視性が失われます。

## 第1層：車両リーフノード

各ドローンはJetson上で**NATSリーフノード**を実行します。

| 項目 | 構成 |
|--------|---------------|
| **プロセス** | リーフモードのnats-server |
| **ストレージ** | SSD/eMMC上のローカルJetStream |
| **接続** | リージョナルハブへの単一のアップストリーム |
| **リソース** | 約50MBのRAM、最小限のCPU |

**リーフノードが提供するもの：**

### ローカルPub/Sub

車載サービスはローカルのNATSインスタンスを介して通信します。

```
Vehicle Gateway ──publish──▶ fleet.prod.veh.VID-001.state.position
                                       │
                                       ▼
                            ┌──────────────────┐
                            │   Local NATS     │
                            │   (Leaf Node)    │
                            └──────────────────┘
                                       │
                                       ▼
AI Perception ◀──subscribe── fleet.prod.veh.VID-001.state.position
```

車載サービス間のメッセージが車両の外に出ることはありません。レイテンシは1ミリ秒未満です。

### ストア・アンド・フォワード

アップストリーム接続が切断されると、リーフノードは次のように動作します。

1. ローカルサービスからのパブリッシュを引き続き受け付ける
2. メッセージをローカルのJetStreamに保存する
3. ハブ宛ての送信メッセージをキューに入れる
4. 接続が回復すると再接続してリプレイする

つまり、**車両は接続が失われている間も動作を継続します**。リンクが回復すると状態が同期されます。

### WAN分離

リーフノードは車両とWANの間のバッファとして機能します。

- **バックプレッシャー** — ハブの処理が追いつかない場合、リーフがローカルでバッファリングする
- **フィルタリング** — サブスクライブされたサブジェクトのみがWANリンクを通過する
- **圧縮** — NATSプロトコルは効率的に圧縮する
- **再接続** — 指数バックオフによる自動再接続

## 第2層：リージョナルハブクラスター

リージョナルハブは地理的エリアごとに車両を集約します。

| 項目 | 構成 |
|--------|---------------|
| **デプロイ** | 3ノードのNATSクラスター（最小構成） |
| **設置場所** | クラウドリージョンまたはエッジデータセンター |
| **ストレージ** | 高速SSD上のJetStream |
| **キャパシティ** | クラスターあたり数百のリーフ接続 |

**リージョナルである理由：**

- **レイテンシ** — リーフノードは近くのハブに接続する
- **帯域幅** — テレメトリはデフォルトでリージョン内に留まる
- **コンプライアンス** — データレジデンシー要件
- **障害の分離** — リージョンの障害が他のリージョンに影響しない

**ハブの役割：**

| 機能 | 説明 |
|----------|-------------|
| **リーフの集約** | 車両のリーフノードからの接続を受け付ける |
| **ストリームストレージ** | デジタルツインのデータをJetStreamに永続化する |
| **コンシューマーのサポート** | フリートダッシュボード、API、分析にデータを提供する |
| **クロスリージョンルーティング** | 必要に応じてグローバル層に転送する |

### クラスター構成

3ノードクラスターは以下を提供します。

- **高可用性** — 単一ノードの障害に耐える
- **データレプリケーション** — JetStreamのストリームをノード間でレプリケートする
- **負荷分散** — リーフ接続をノード間で分散する

```yaml
# Example hub cluster configuration
cluster:
  name: hub-americas
  routes:
    - nats://hub-americas-1:6222
    - nats://hub-americas-2:6222
    - nats://hub-americas-3:6222

jetstream:
  store_dir: /data/jetstream
  max_memory_store: 4GB
  max_file_store: 100GB

leafnodes:
  port: 7422
  authorization:
    users:
      - user: vehicle
        password: $VEHICLE_PASSWORD
        allowed_connection_types: ["LEAFNODE"]
```

## 第3層：グローバル（オプション）

複数のリージョンにまたがるフリートでは、グローバル層によって以下が可能になります。

| 機能 | 説明 |
|----------|-------------|
| **クロスリージョンミラーリング** | リージョナルハブ間でストリームをレプリケートする |
| **グローバル集約** | フリート全体のダッシュボードと分析 |
| **コマンドルーティング** | 任意のリージョンの車両にコマンドを送信する |
| **災害復旧** | リージョン間のフェイルオーバー |

**実装オプション：**

1. **NATSスーパークラスター** — ゲートウェイ接続を介してリージョナルクラスターをフェデレーションする
2. **JetStreamミラーリング** — 特定のストリームを中央拠点にレプリケートする
3. **アプリケーションレベル** — リージョナルAPI間のカスタム同期

ほとんどのフリートは単一リージョン内で運用されており、当初はグローバル層を必要としません。

## このトポロジーの利点

### 低レイテンシのローカルPub/Sub

車載通信は**1ミリ秒未満**です。

```
MAVLink message received
    └─▶ Vehicle Gateway publishes to local NATS
        └─▶ AI Perception subscribes from local NATS
            └─▶ Total latency: <1ms
```

車載通信にWANのラウンドトリップは発生しません。

### WAN分離

車両の運用は**接続が失われている間も継続します**。

- 認識システムは動作し続ける
- 状態はローカルに蓄積される
- コマンドは実行待ちとしてキューに入る
- 再接続時に自動的に同期される

### フリート全体のデジタルツインリプレイ

JetStreamにより、フリート全体にわたる**時系列クエリ**が可能になります。

```
# Replay vehicle state from 10 minutes ago
nats stream get TWIN_STATE --start-time="2024-01-15T10:00:00Z"

# Subscribe to real-time state updates
nats sub "fleet.prod.veh.*.state.position"
```

すべての車両の状態履歴をリージョナルハブからクエリできます。

### スケーラブルなアーキテクチャ

このトポロジーは水平方向にスケールします。

| スケールポイント | アプローチ |
|-------------|----------|
| **車両の増加** | 既存のハブにリーフ接続を追加する |
| **スループットの向上** | ハブクラスターにノードを追加する |
| **リージョンの追加** | 追加のリージョナルハブをデプロイする |
| **グローバル展開** | スーパークラスターを介してハブを接続する |

## 接続フロー

車両の電源が入ると：

```
1. Jetson boots, NATS leaf node starts
2. Leaf node reads hub address from config
3. TLS connection established to regional hub
4. Authentication via credentials
5. Leaf node advertises local subjects
6. Hub routes relevant subscriptions to leaf
7. Bidirectional message flow begins
```

接続が切断されると：

```
1. Leaf node detects connection loss
2. Local pub/sub continues uninterrupted
3. Outbound messages queue locally
4. Reconnection attempts with backoff
5. On reconnect, queued messages replay
6. Stream state synchronizes
```

## セキュリティ

すべての接続は認証され、暗号化されます。

| 接続 | セキュリティ |
|------------|----------|
| **リーフ → ハブ** | TLS 1.3、クレデンシャル認証 |
| **ハブクラスター** | TLS、認証済みクラスタールート |
| **ハブ → グローバル** | TLS、ゲートウェイ認証 |

クレデンシャルは車両ごとにプロビジョニングされるため、以下が可能になります。

- 個々の車両単位での失効
- 車両ごとの監査証跡
- 接続ごとのレート制限

認可モデルは**グラントによる分散型セキュリティ**をサポートしています。サードパーティは、中央での調整なしに、スコープと期限が限定されたアクセス権を受け取ることができます。クレデンシャル管理とサードパーティ統合の詳細については、[認可とグラント]({{< relref "/fleet/authorization" >}})を参照してください。

## まとめ

| 層 | 目的 | デプロイ先 |
|------|---------|------------|
| **リーフ（車両）** | ローカルPub/Sub、ストア・アンド・フォワード | Jetson上 |
| **ハブ（リージョナル）** | 集約、永続化、コンシューマー | クラウド/エッジデータセンター |
| **グローバル（オプション）** | クロスリージョン、フリート全体のビュー | 中央クラウド |

このトポロジーにより、車両は独立して動作しながら、フリート全体の可視性と制御が維持されます。
