## 地面车辆车队的硬件

地面车辆（轿车、卡车、AGV 和自动驾驶平台）采用与无人机相同的车队架构，但使用适合车辆的硬件、协议和安全模型。

---

## 协议选项

地面车辆使用行业标准协议进行通信：

### CAN 总线

| 方面 | 详情 |
|--------|---------|
| **标准** | CAN 2.0B / CAN FD |
| **数据速率** | 500kbps (CAN) / 5Mbps (CAN FD) |
| **消息格式** | DBC 文件定义信号编码 |
| **物理层** | 差分对，在高噪声环境中依然可靠 |

**CAN 总线提供：**
- 直接访问车辆系统（发动机、变速器、制动系统）
- 实时遥测（车速、转速、燃油、温度）
- 诊断故障码（OBD-II / J1939）
- 后装设备集成

### J1939（重型车辆）

适用于卡车、客车和重型设备：

| 方面 | 详情 |
|--------|---------|
| **标准** | SAE J1939 |
| **传输** | 250kbps 的 CAN 2.0B |
| **寻址** | 带 PGN/SPN 的 29 位标识符 |
| **应用** | 发动机、变速器、制动系统、挂车 |

**J1939 提供：**
- 跨制造商的标准化参数组（PGN）
- 整个车队一致的遥测数据
- 与车载信息服务平台集成
- 符合监管要求

### ROS 2（自动驾驶平台）

适用于专门打造的自动驾驶车辆：

| 方面 | 详情 |
|--------|---------|
| **中间件** | ROS 2 Humble / Iron |
| **传输** | DDS（Cyclone DDS、Fast DDS） |
| **消息类型** | 标准类型（sensor_msgs、geometry_msgs）+ 自定义类型 |
| **QoS** | 可配置的可靠性和持久性 |

**ROS 2 提供：**
- 原生传感器集成（LiDAR、摄像头、IMU）
- 面向机器人的标准消息类型
- 直接将话题桥接到 NATS
- 仿真兼容性（Gazebo、CARLA）

## 硬件栈

### 计算平台

地面车辆通常使用加固型工业计算设备：

| 平台 | 使用场景 | 备注 |
|----------|----------|-------|
| **NVIDIA Jetson AGX Orin** | 自动驾驶车辆 | 高性能感知 |
| **NVIDIA Jetson Orin NX** | 车队车辆 | 兼顾性能与成本 |
| **工业 PC** | 仅车载信息服务 | 成本较低，无需 GPU |
| **Neousys** | 加固型车载 | 宽温范围，点火控制 |

**计算设备职责：**
- 车辆网关（CAN/ROS 2 到 NATS）
- NATS 叶节点
- 边缘 AI 推理（可选）
- 连接中断期间的存储转发

### CAN 接口

| 设备 | 接口 | 备注 |
|--------|-----------|-------|
| **PEAK PCAN-USB** | USB | 流行，支持完善 |
| **Kvaser Leaf Light** | USB | 工业级 |
| **SocketCAN 设备** | USB/PCIe | Linux 原生支持 |
| **Jetson 原生 CAN** | 内置 | AGX Orin 上可用 |

### 连接方式

| 方式 | 使用场景 |
|--------|----------|
| **4G/5G 蜂窝网络** | 车队主要连接方式 |
| **WiFi** | 场站/设施内作业 |
| **以太网** | 有线停靠站连接 |
| **卫星** | 偏远/乡村地区作业 |

## 车辆类型

### 乘用车（轿车）

| 组件 | 典型选型 |
|-----------|-------------------|
| **协议** | CAN 总线（OBD-II 端口或直连） |
| **计算** | Jetson Orin NX 或工业 PC |
| **电源** | 12V 车辆电气系统 |
| **连接** | 4G/5G 蜂窝网络 |
| **安全** | 驾驶员接管、紧急停止 |

**使用场景：** 网约车车队、租赁车辆、配送车辆

### 商用车（卡车）

| 组件 | 典型选型 |
|-----------|-------------------|
| **协议** | J1939（基于 CAN） |
| **计算** | 加固型工业 PC 或 Jetson |
| **电源** | 12V/24V 车辆电气系统 |
| **连接** | 4G/5G + 卫星备份 |
| **安全** | 驾驶员接管、ELD 合规 |

**使用场景：** 长途物流、配送车队、服务车辆

### 自动导引车（AGV）

| 组件 | 典型选型 |
|-----------|-------------------|
| **协议** | ROS 2 原生或专有协议 |
| **计算** | Jetson AGX Orin |
| **电源** | 24V/48V 电池系统 |
| **连接** | WiFi（设施内）+ 蜂窝网络（户外） |
| **安全** | 紧急停止、安全等级传感器 |

**使用场景：** 仓储物流、采矿、农业、港口作业

## 安全模型

地面车辆的安全机制与无人机不同，但遵循相同的原则：

### 权限层级

```
Manual Override (highest authority)
    │
    ├── Steering wheel / brake pedal (driver present)
    ├── E-stop button (AGVs)
    └── Remote operator console
    │
    ▼
Autonomous System (software control)
    │
    ├── Perception → Planning → Control
    └── Geofencing, speed limits, operational domain
    │
    ▼
Fleet Management (lowest authority)
    │
    └── Mission assignment, routing, monitoring
```

### 故障安全行为

| 触发条件 | 无人机对应行为 | 地面车辆响应 |
|---------|------------------|------------------------|
| 通信中断 | 返航 | 原地停车 / 靠边停车 |
| 传感器故障 | 立即降落 | 安全停车，通知操作员 |
| 越出地理围栏 | 返回边界 | 在边界处停车 |
| 紧急停止触发 | 切断电机 | 立即制动 |
| 电量不足 | 返航 / 降落 | 返回场站 / 安全停车 |

### 网络安全

**与无人机原则相同：** NATS 绝不参与控制回路。

| NATS 负责的工作 | NATS 不负责的工作 |
|----------------|---------------------|
| 遥测数据采集 | 实时转向 |
| 任务分配 | 制动指令 |
| 车队协调 | 油门控制 |
| 监控与告警 | 安全关键决策 |

车辆的车载系统负责所有安全关键功能。网络中断意味着失去监控，而不是失去对车辆的控制。

## 网关实现

车辆网关将车辆原生协议桥接到 NATS：

```
┌─────────────────────────────────────────────────────────────────┐
│                    GROUND VEHICLE GATEWAY                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   CAN Bus ─────► DBC Parser ─────► Telemetry Subjects           │
│                                                                  │
│   J1939 ───────► PGN Decoder ────► Telemetry Subjects           │
│                                                                  │
│   ROS 2 ───────► Topic Bridge ───► Telemetry Subjects           │
│                                                                  │
│   Commands ◄───────────────────── Command Subjects              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                      NATS JETSTREAM                              │
│   fleet.prod.veh.{vehicle_id}.state.*                           │
│   fleet.prod.veh.{vehicle_id}.evt.*                             │
│   fleet.prod.veh.{vehicle_id}.cmd.*                             │
└─────────────────────────────────────────────────────────────────┘
```

**网关职责：**
- 协议转换（CAN/J1939/ROS 2 → 通用遥测格式）
- 状态降采样（将高频 CAN 数据降低到可处理的速率）
- 事件提取（检测状态变化、阈值）
- 指令校验（执行前进行安全检查）
- 存储转发（连接中断期间缓存数据）

## 主题映射

地面车辆使用与无人机相同的主题层级：

| 主题 | 地面车辆内容 |
|---------|----------------------|
| `fleet.prod.veh.{id}.state.pos` | GPS 位置、航向 |
| `fleet.prod.veh.{id}.state.vel` | 速度、加速度 |
| `fleet.prod.veh.{id}.state.health` | 发动机状态、诊断信息 |
| `fleet.prod.veh.{id}.state.fuel` | 燃油液位 / 电池 SOC |
| `fleet.prod.veh.{id}.evt.trip` | 行程开始/结束事件 |
| `fleet.prod.veh.{id}.evt.geofence` | 区域进入/离开 |
| `fleet.prod.veh.{id}.cmd.mission` | 路线分配 |

主题结构与车辆类型无关。混合使用无人机和卡车的车队采用完全相同的模式。

## 集成模式

### ELD 合规（美国卡车）

电子记录设备要求：
- 工作时长（Hours of Service）跟踪
- 驾驶员身份识别
- 位置记录
- 向主管部门传输数据

网关采集 J1939 发动机数据，并与 ELD 合规系统集成。

### 车载信息服务集成

现有车载信息服务平台可通过以下方式接入：
- NATS 授权（订阅特定车辆）
- REST API（查询历史数据）
- Webhook 事件（实时告警）

### 车队管理系统

与企业 TMS/FMS 集成：
- 车辆分配
- 路线优化
- 燃油管理
- 维护计划

## 总结

| 方面 | 无人机 | 地面车辆 |
|--------|--------|-----------------|
| **协议** | MAVLink | CAN 总线 / J1939 / ROS 2 |
| **计算** | Jetson Orin Nano | Jetson / 工业 PC |
| **电源** | 4S LiPo (14.8V) | 12V/24V/48V 车辆电气系统 |
| **安全接管** | 遥控发射器 | 方向盘 / 紧急停止 |
| **故障安全** | 返航 | 原地停车 |
| **法规** | 航空（FAA/EASA） | 道路运输（DOT） |
| **车队架构** | **完全相同** | **完全相同** |
