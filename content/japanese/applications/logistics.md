## 3つのプラットフォームが融合するとき

**Fleet + Publish + Foundation** が組み合わさることで、新しいものが生まれます。それは、人間のオペレーターが完全に接続されたシステムのインテリジェントなエッジポイントとなる、AI駆動のフィールドオペレーションです。

iPadを持つトラックドライバーは、AIが指示する集荷ルートを受け取ります。システムはすべての車両の位置を把握しています。オペレーターは音声やテキストでルートを更新でき、AIは影響を受けるすべてのルートを即座に再構成します。

---

## 課題：動的な世界における静的なルート

従来のフィールドオペレーションは前夜に計画されます：

- **ルート計画** — 配車担当者が手作業でルートを作成するか、夜間バッチ最適化を使用
- **直前の変更** — ドライバーが病欠？道路が封鎖？電話、再計画、混乱
- **リアルタイムの可視性がない** — 「47号車はどこ？」を知るには無線連絡が必要
- **紙ベースのプロセス** — 作業指示書を印刷し、完了状況を手作業で再入力
- **情報のサイロ化** — ドライバーが知っていることを配車担当者は知らず、顧客はまったく把握していない

現実が計画からずれると、システム全体が適応に苦労します。

## 事例：ごみ収集の再構想

このアーキテクチャがどのように機能するかの具体例：

### 朝：AIが1日を計画

1. システムはすべての集荷場所、優先度、コンテナの充填レベル（IoTセンサー）を把握
2. AIが各トラックの最適ルートを計算—距離を最小化し、時間枠を遵守
3. シフト開始前にルートがドライバーのタブレットへ自動配信
4. 各ドライバーは、ターンバイターンナビ付きの2D/3Dで自分専用のルートを確認

### 運用中：リアルタイムの適応

**ドライバー1の報告：**「123 Main St が工事のため通行止め」

```
Driver speaks into tablet
    └─▶ SST converts to text
    └─▶ System marks location as blocked
    └─▶ AI refactors all affected routes
    └─▶ Updated routes push to affected drivers
    └─▶ Total time: seconds
```

電話は不要。配車担当者の介入も不要。システムが対処します。

**その間に：**
- 配車ダッシュボードにすべてのトラックがリアルタイムで表示
- 顧客ポータルに集荷の到着予定時刻（ETA）を表示
- すべての完了が自動的に記録
- すべての変更が完全な来歴とともに監査

### ヒューマン・イン・ザ・ループ

オペレーターはいつでもAIをオーバーライドできます：

| 入力方法 | 例 | システムの応答 |
|--------------|---------|-----------------|
| **音声（SST）** | 「456 Oak Ave はスキップ、顧客不在」 | スキップとしてマークし、ルートを調整 |
| **タッチ** | 地図上の場所をタップし、「通行止め」を選択 | すべてのルートから除外 |
| **フォーム** | メモ付きでサービスフォームを記入 | 完了を記録し、請求をトリガー |
| **オーバーライド** | ルートをドラッグして順序を変更 | 変更を受け入れ、以降を再最適化 |

AIは人間の判断を補強するものであり、置き換えるものではありません。

### 音声駆動のルート再構成

音声テキスト変換（SST）により、ハンズフリーでシステムを更新できます：

| ドライバーの発話 | システムの動作 |
|-------------|-------------|
| 「123 Main が工事で通行止め」 | 場所を通行止めとしてマークし、影響を受けるすべてのルートを再構成 |
| 「次の集荷はスキップ、誰もいない」 | ルートから除外し、顧客に通知し、ETAを調整 |
| 「Oak Street でコンテナがあふれている」 | 優先フラグを付け、より大きなトラックへ再割り当てする場合あり |
| 「15分休憩します」 | 以降のすべてのETAを調整し、影響を受ける顧客に通知 |
| 「ルート完了」 | ルートを終了し、ダッシュボードを更新し、請求をトリガー |

配車への電話も、無線でのやり取りも不要。ドライバーが話し、AIが聞き、システムが適応します。

## パブリッシング：単一ソース、あらゆるチャネル

[Publish プラットフォーム]({{< relref "/platform/publish" >}})は、単一の信頼できる情報源からすべての出力を生成します。

### ロジスティクスの出力

| ソース定義 | 生成される出力 |
|-------------------|-------------------|
| **集荷レコード** | タブレット画面、PDFマニフェスト、顧客向けSMS、キオスク表示 |
| **ルート計画** | ドライバー向けターンバイターン、配車ダッシュボード、顧客向けETA |
| **サービスフォーム** | デジタルフォーム、印刷可能なPDF、OCRスキャンされた紙 |
| **日次サマリー** | メールレポート、ダッシュボードウィジェット、コンプライアンス用エクスポート |

**1つの定義。複数の出力。** ソースを変更すれば、すべてのチャネルが自動的に更新されます。

### 多言語の現場チーム

現場作業員が異なる言語を話す？Publishが翻訳を処理します：

- ドライバー1のタブレット：英語
- ドライバー2のタブレット：スペイン語
- 顧客ポータル：顧客の希望言語
- PDFマニフェスト：企業標準

同じデータを、ローカライズされた表示で。重複したコンテンツ管理は不要です。

### フィードバックするフォーム

サービス完了フォームはシステムへと還流します：

```
Driver completes pickup form
    └─▶ Photo attached (proof of service)
    └─▶ Notes recorded ("Container damaged")
    └─▶ Time stamped automatically
    └─▶ GPS coordinates captured
    └─▶ Data syncs via Foundation
    └─▶ Billing system updated
    └─▶ Customer notified
    └─▶ Maintenance ticket created (if needed)
```

フォームは単なるデータ収集ではありません。下流の自動化のトリガーです。

### データ主権

データはどこへ行くのか？[WellKnown Gateway]({{< relref "/platform/publish#wellknown-gateway-data-sovereignty" >}})により、Salesforce、車両追跡システム、請求プロバイダーなどの外部プラットフォームへパブリッシュする場合でも、データの所有権はお客様にあります。

**基本原則：** お客様がプラットフォームへパブリッシュするのです。データを所有するのはプラットフォームではなく、お客様です。

## Fleet統合：データソースとしての車両

**Fleetアーキテクチャ**は車両レイヤーを提供します。トラックはデータ豊富なデジタルツインになります。

### トラックが知っていること

すべての車両がCANバスゲートウェイ経由でテレメトリーをストリーミングします：

| データポイント | ソース | 用途 |
|------------|--------|-----|
| **GPS位置** | テレマティクスモジュール | リアルタイム追跡、ETA計算 |
| **エンジン状態** | ECU | 健全性監視、メンテナンスアラート |
| **燃料レベル** | 燃料センサー | 航続距離の推定、給油スケジューリング |
| **速度** | 車輪センサー | 安全監視、ルートのタイミング |
| **診断** | OBD-II / J1939 | 予知保全 |
| **ドア状態** | ボディコントローラー | サービスの検証 |
| **重量** | ロードセル | 積載容量管理 |

トラックは単なる輸送手段ではありません。移動するセンサープラットフォームです。

### デジタルツインの同期

すべてのトラックはシステム内にデジタルツインを持ちます：

```
Physical Truck                    Digital Twin
─────────────                    ────────────
Position: 34.05°, -118.24°   →   state.position
Fuel: 67%                    →   state.fuel
Engine: Running              →   state.engine
Speed: 25 mph                →   state.speed
Door: Closed                 →   state.door
Weight: 3,400 lbs            →   state.weight
```

配車担当者は現実を見る。AIは現実に基づいて最適化する。顧客は正確なETAを得る。

## Foundation：すべてをオフラインファーストで

**Foundationプラットフォーム**は、接続が途切れてもシステムが動作し続けることを保証します。

### オフラインが重要な理由

フィールドオペレーションはネットワークが途切れる場所で行われます：

- 地下駐車場
- 電波が不安定な地方
- トンネルや地下道
- イベント時の混雑したエリア
- 国境地帯（ローミングの空白）

オフライン時にアプリがフリーズすれば、業務もフリーズします。それは許されません。

### Automerge CRDT：競合のない同期

オフライン中に行われた変更は、接続が回復するとクリーンにマージされます：

```
Driver A (online):    Marks pickup complete at 9:15am
Driver B (offline):   Marks same pickup skipped at 9:14am (tunnel)

Driver B reconnects:
    └─▶ Automerge detects conflict
    └─▶ Applies "last write wins" or custom merge rule
    └─▶ Both changes preserved in history
    └─▶ Alert triggers for dispatcher review
    └─▶ No data loss, no app crash
```

従来のデータベースではデータが破損または消失します。CRDTはそれを適切に処理します。

### あらゆる場所にSQLite

すべてのデバイスが完全なローカルデータベースを持っています：

- **ドライバーのタブレット**：ルート、顧客、フォーム、履歴
- **配車ダッシュボード**：フリートの状態、アラート、分析
- **顧客ポータル**：自身のサービス記録、今後の集荷予定

ネットワークがない？問題ありません。アプリは必要なものをすべてローカルに持っています。

## 技術基盤

### オフライン耐性

接続が切れてもシステムは動作し続けます：

```
Connectivity lost
    └─▶ App continues with local SQLite
    └─▶ Changes queue in Automerge CRDT
    └─▶ Position caches locally

Connectivity returns
    └─▶ Automerge merges all changes
    └─▶ No conflicts, no data loss
    └─▶ System catches up automatically
```

フィールドオペレーションはネットワークの問題で止まるわけにはいきません。このアーキテクチャがそれを保証します。

### リアルタイム同期

接続時には、変更が即座に伝播します：

```
Driver completes pickup
    └─▶ Form data saves to local SQLite
    └─▶ Automerge syncs to NATS
    └─▶ JetStream persists event
    └─▶ Dashboard updates
    └─▶ Customer notified
    └─▶ Total latency: <1 second
```

### 通知アーキテクチャ

すべてのデバイスが関連するNATSサブジェクトをサブスクライブします：

| サブジェクトパターン | 受信者 |
|-----------------|--------------|
| `fleet.prod.veh.{id}.route.*` | 当該ドライバーのデバイス |
| `fleet.prod.veh.*.state.pos` | 配車ダッシュボード |
| `fleet.prod.customer.{id}.*` | 顧客ポータル |

変更は一度パブリッシュされるだけで、関係するすべての当事者に自動的に配信されます。

## セキュリティとデータ主権

業務データはお客様のものであり続けます：

| 原則 | 実装 |
|-----------|----------------|
| **自己主権** | データはお客様のインフラまたは当社のインフラに保存—選択はお客様次第 |
| **WellKnown Gateway** | ロックインなしでプラットフォームへパブリッシュ |
| **エンドツーエンド暗号化** | 転送中および保存時のデータを暗号化 |
| **ゼロトラスト** | すべてのデバイスを認証し、すべてのリクエストを認可 |
| **監査証跡** | すべての変更を完全な来歴とともに記録 |
| **オフラインファースト** | データはクラウドだけでなくデバイス上に存在 |
